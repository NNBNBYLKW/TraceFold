# TraceFold Media Desktop Stage 3 手工验收指南

> **安全警告：只使用可丢弃的媒体副本和三个全新的隔离目录。不要选择个人文件夹、现有正式库、Web 版数据目录或仍在使用的旧测试目录。**

## 验收准备

- 解压 `TraceFold-MediaDesktop-Stage3-win-x64.zip`，直接运行其中的 `TraceFold.Media.exe`。
- 新建三个互不相同、互不包含的空目录：待入库、正式文件库、工作目录。
- 准备仓库固定样本 `paired.mp4`、`paired.m4a` 的副本；另准备一张图片和一个普通视频副本。
- 打开任务管理器的“详细信息”页，以便检查 `TraceFold.Media.exe` 和 `ffmpeg.exe`。
- 每一步记录“通过/失败”、截图、异常现象和使用的测试文件名。

## 15 步验收

1. 启动软件，进入“设置”，选择三个隔离目录并保存，然后重启。
   预期：三个路径被保留；设置页显示前置处理工具“可用”及 FFmpeg 版本；只出现一个原生软件窗口，不打开浏览器。

2. 把同名 `paired.mp4`、`paired.m4a` 副本一起放入待入库目录并立即刷新，等待至少 2 秒后再次刷新。
   预期：先显示等待稳定，软件不崩溃或闪退。

3. 查看稳定后的待入库列表，不点击任何处理按钮。
   预期：两个源文件只形成一个“需要前置处理”的视频项目，而且不会自动开始处理。

4. 在该项目中填写自定义显示名称、两位作者、一个系列和多个内容标签，切换项目后再返回。
   预期：资料保存成功；允许多作者和多标签，但同时只能选择一个系列；显示名称不改变两个物理文件名。

5. 点击“开始处理”。
   预期：项目依次显示“排队中”“处理中”，展示当前步骤与单调递增的数字进度；处理必须由本次点击触发。

6. 处理成功后使用右侧预览播放视频。
   预期：预览可以播放，画面与声音同时存在；未通过视频流和音频流验证的输出不得进入可预览/可入库状态。

7. 处理成功但尚未正式入库时检查待入库目录。
   预期：原 `paired.mp4` 与 `paired.m4a` 都仍存在。

8. 点击“正式入库”。
   预期：正式库出现 `paired.mp4`；物理文件名沿用原 MP4 名称，自定义显示名称只在软件中显示。

9. 检查待入库目录和工作目录。
   预期：正式提交验证成功后，原 MP4、原 M4A 和对应处理输出均被清理；其他无关文件不受影响。

10. 准备两组名称不同的同名 MP4/M4A 测试副本，分别点击“开始处理”。
    预期：任意时刻最多一个任务为“处理中”，另一个显示“排队中”；第一个完成后第二个才开始。

11. 再准备两组测试副本；开始两个任务后，对正在处理的项目点击“停止”。
    预期：当前任务转为“已中断”，原文件保留；队列中的下一个任务可以开始；已中断任务不会自动重试。

12. 开始一项处理并在处理中关闭主窗口，然后在任务管理器中检查进程，再重启软件。
    预期：`TraceFold.Media.exe` 和由它启动的 `ffmpeg.exe` 均退出；重启后任务显示已中断，不自动恢复处理，原文件保留。

13. 让一项处理成功但不要入库，随后在资源管理器中修改或替换任一原文件，再刷新或尝试入库。
    预期：旧处理输出失效，软件拒绝正式入库并要求重新处理；修改后的源文件不被删除。

14. 暂时把包内 `tools\ffmpeg` 文件夹改名后启动软件，再放入普通图片和普通视频；测试完成后恢复文件夹名。
    预期：设置页显示稳定的 `processing.tool_missing` 诊断，前置处理按钮不可用；刷新、资料编辑、普通图片/视频预览、正式入库和正式库浏览仍可用。

15. 恢复工具后，回归图片与普通视频的扫描、预览、资料、词表、正式入库和正式库编辑，并关闭软件检查进程。
    预期：Stage 2 普通流程无回归；文件入库后物理文件名不变；关闭后没有残留 `TraceFold.Media.exe` 或包内 `ffmpeg.exe`。

## 发布门槛与记录

以下任一现象都应判定失败并停止使用该测试目录：覆盖正式文件、失败时误删源文件、显示名称修改物理文件名、并行运行多个 FFmpeg、关闭后残留自有 FFmpeg、使用包外工具，或普通图片/视频因工具缺失而不可入库。

当前没有干净的 Windows 11 x64 虚拟机，因此本机受限 `PATH` 的离线烟雾测试只能作为阶段检查；“全新 Windows 11 x64 机器验证”必须记录为**未执行**，不能记录为通过。
