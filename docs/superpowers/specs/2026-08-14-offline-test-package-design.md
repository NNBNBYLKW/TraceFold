# TraceFold Windows 离线测试包设计

## 目标与边界

为媒体文件库生成一份 Windows 轻量测试版，目标平台固定为 Windows 10/11 x64 与 Python 3.12 x64。测试包必须在无网络环境完成安装和运行，使用 Edge 应用模式提供独立窗口，并将所有测试数据保存在 ZIP 解压目录内。

测试包不捆绑 Python、Node.js、FFmpeg、FFprobe 或 Edge。Python 3.12 x64、FFmpeg、FFprobe 和 Edge 是测试电脑的前置条件。包内提供完整 Python 离线 wheels，因此安装和运行都不访问网络。前端使用预先构建的静态产物，测试电脑不需要 Node.js。

这是测试发行物，不是正式安装程序：不注册 Windows 服务、不写注册表、不创建卸载器、不自动升级，也不修改旧 TraceFold 应用的入口和数据。

## 发行架构

采用单进程架构。FastAPI 同时提供：

- `/api/*` 业务接口；
- `/assets/*` 前端静态资源；
- `/` 及非 API 前端路由的 React SPA 入口。

测试包只启动一个 Python 后端进程并监听 `127.0.0.1:8100`。启动器等待健康检查通过后，以 Edge `--app=http://127.0.0.1:8100` 打开独立窗口。前端和 API 同源运行，测试版不需要 CORS 配置，也不需要额外静态文件服务器或 Node 进程。

开发环境保持现有行为：如果没有随应用部署的前端构建目录，API 仍可独立运行，Vite 开发服务器仍通过 `VITE_API_BASE_URL` 访问 API。静态托管能力通过明确的部署目录配置启用，不依赖当前工作目录猜测。

## 包内结构

发行物名称为 `TraceFold-Test-0.1.0-win-x64.zip`，解压后结构如下：

```text
TraceFold-Test-0.1.0/
├─ app/
│  ├─ media_api/               后端 Python 包
│  ├─ migrations/              Alembic 迁移
│  ├─ alembic.ini
│  └─ web/                     前端生产构建产物
├─ wheelhouse/                 Python 3.12 Windows x64 离线 wheels
├─ data/
│  ├─ inbox/
│  ├─ library/
│  └─ work/
├─ runtime/
│  ├─ edge-profile/
│  └─ logs/
├─ 安装测试环境.cmd
├─ 启动 TraceFold.cmd
└─ 测试版使用说明.txt
```

首次安装后，包根目录还会生成 `.venv/` 与 `data/media.sqlite3`。ZIP 中的数据目录只含用于保留空目录的占位文件，不含数据库、媒体、预览、缓存、日志或 E2E 数据。

程序文件、运行时文件和用户测试数据互相分离。升级时解压到新的版本目录，不自动覆盖旧版本；用户明确选择后才能复制旧 `data`。本测试版不提供自动数据搬迁。

## 离线依赖

构建脚本在有网络的构建电脑上，根据锁定依赖为 CPython 3.12、Windows x64 下载 wheels 到 `wheelhouse`。运行包的安装脚本只执行本地安装：

```text
python -m pip install --no-index --find-links wheelhouse ...
```

安装脚本不得省略 `--no-index`，不得配置在线备用源。构建阶段需要验证所有运行依赖都有兼容 wheel，并生成 wheel 文件清单与 SHA-256。测试包不包含测试工具和 Playwright 浏览器，除非它们是运行时的直接依赖。

## 首次安装流程

用户双击 `安装测试环境.cmd` 后：

1. 检查系统为 Windows x64。
2. 解析 `py -3.12` 或 `python`，确认解释器是 CPython 3.12 x64。
3. 检查 `ffmpeg`、`ffprobe` 和 `msedge.exe` 是否可用。
4. 在包根目录创建 `.venv`。
5. 使用 `wheelhouse` 和 `--no-index` 安装运行依赖与 TraceFold 后端。
6. 创建 `data/inbox`、`data/library`、`data/work`、`runtime/edge-profile` 和 `runtime/logs`。
7. 使用包内相对路径设置四个 TraceFold 运行路径。
8. 对 `data/media.sqlite3` 执行 `alembic upgrade head`。
9. 输出中文成功信息；失败时保持窗口打开并指出日志位置。

安装过程必须可重复执行。已有 `.venv` 和数据库时，脚本验证环境并再次执行安全的依赖安装与迁移，不删除数据。

## 日常启动与退出

用户双击 `启动 TraceFold.cmd` 后：

1. 验证 `.venv`、FFmpeg、FFprobe、Edge 和必要目录。
2. 检查 `127.0.0.1:8100` 是否可绑定；端口已占用时中止，不结束占用者。
3. 设置基于包根目录的 inbox、library、work、数据库和前端静态目录。
4. 启动唯一的 FastAPI 子进程，并将标准输出和错误写入带时间戳的日志。
5. 轮询 `/health`；超时或进程提前退出时不打开 Edge，显示日志位置。
6. 使用独立 `runtime/edge-profile` 启动 Edge 应用窗口。
7. 等待本次启动的 Edge 进程退出。
8. 仅终止本次启动的 FastAPI 子进程，并确认端口释放。

启动器不得按进程名结束所有 Python 或 Edge 进程。若 Edge 启动后派生进程导致启动器无法可靠等待具体窗口，则启动器通过专用 Edge 配置目录定位本次实例，并在设计实现测试中验证退出语义；不得退化为结束全部 Edge 进程。

Edge 不存在时明确提示安装 Edge，不静默打开普通浏览器。后端命令窗口可以最小化，但需保留一个可关闭、可查看错误的控制入口。

## 静态前端托管

后端新增可选的前端构建目录配置。启用时：

- 目录必须存在并包含 `index.html`；否则启动失败并给出清晰诊断。
- 真实静态文件从构建目录读取，并阻止路径逃逸。
- `/api`、`/health`、OpenAPI 和事件流路由优先于 SPA 回退。
- 对不存在的非 API GET 路径返回 `index.html`，支持 React 客户端路由。
- 非 GET 请求或不存在的 API 路径不能被 SPA 回退吞掉。

开发、单元测试和 E2E 在不配置该目录时继续使用原有前后端分离方式。

## 构建流程

仓库新增一个可重复执行的 Windows 打包入口。构建流程：

1. 验证工作树和工具链，读取测试版版本号。
2. 执行前端单元测试和生产构建。
3. 执行后端测试。
4. 为 Python 3.12 Windows x64 下载锁定运行时 wheels。
5. 在临时暂存目录组装 `app`、`wheelhouse`、启动脚本、说明和空数据目录。
6. 排除源码测试、Node 模块、Git 文件、数据库、媒体、缓存、日志、`.env` 和 E2E 数据。
7. 生成包内文件清单与 SHA-256。
8. 压缩为 `dist/TraceFold-Test-0.1.0-win-x64.zip`。
9. 生成同名 `.sha256` 校验文件。

暂存与清理只针对构建脚本创建并验证过的专用发行目录，不能使用用户主目录、仓库根目录、通配符或未解析环境变量作为递归删除目标。

## 错误处理

- Python 版本或架构不符：安装中止，明确要求 Python 3.12 x64。
- 缺少 FFmpeg 或 FFprobe：安装或启动中止，提示将其加入 `PATH`。
- 缺少 Edge：安装或启动中止，不回退普通浏览器。
- wheel 不完整、哈希不符或发生网络访问：安装失败，不在线补齐。
- 数据目录不可写：启动前失败，不创建部分运行状态。
- 端口 8100 已占用：启动中止，不结束其他程序。
- 数据库迁移失败：不启动服务，保留数据库和日志供诊断。
- API 健康检查失败：不打开 Edge，并停止本次后端子进程。
- Edge 关闭：只停止本次后端子进程；数据库和媒体保留。

所有用户可操作错误使用中文提示，并提供下一步修复建议。详细诊断写入 `runtime/logs`，日志不得记录媒体内容。

## 验证与验收

代码验证包括：

- 后端静态托管单元/API 测试，覆盖路由优先级、SPA 回退、缺失构建目录和路径安全。
- 安装和启动脚本的可测试核心逻辑，覆盖 Python/架构检查、离线 pip 参数、端口占用、健康检查失败和进程清理。
- 构建脚本安全测试，证明只清理专用暂存目录并排除运行数据。
- 现有后端、前端、构建和 6 条媒体 E2E 验收全部继续通过。

发行物验证在新的临时目录执行：

1. 解压 ZIP。
2. 断网或通过安装日志确认 pip 使用 `--no-index` 且没有网络访问。
3. 创建虚拟环境并安装全部 wheels。
4. 迁移空数据库。
5. 启动服务并验证 `/health`、前端首页和一个 API 请求。
6. 启动与关闭 Edge 应用窗口，确认端口随后释放。
7. 重新启动，确认数据库和文件仍存在。
8. 人工验证图片入库、MP4/M4A 合并、三种冲突选择和重启恢复。

最终交付物包括 ZIP、ZIP 的 SHA-256 文件、构建日志、文件清单和测试版使用说明。

## 非目标

本阶段不提供正式安装器、自动更新、桌面快捷方式、代码签名、内置 Python、内置 FFmpeg、内置 Edge/WebView2、Windows 服务、后台托盘、远程访问、旧系统删除、生产数据迁移或默认入口切换。这些能力需要单独设计与评审。
