## 1. 目标

Stage 5A 首先解决待入库文件较多时重复选择、重复填写资料、逐个启动处理和逐个请求入库的问题。

本阶段保持已经确认的主路径：

```text
刷新 → 可选前置处理 → 标注资料 → 正式入库
```

在不取消任何人工确认点的前提下，增加一条资源管理器式批量路径：

```text
资源管理器式多选
  → 批量追加 / 移除 / 替换资料
  → 可选：批量开始前置处理
  → 批量正式入库汇总确认
  → 可直接入库项继续
  → 需处理、冲突或异常项保留
```

批量能力是现有单项目用例之上的应用层编排，不建立第二套入库、处理、冲突或恢复状态机。

## 2. Stage 5 拆分

总设计中的 Stage 5 包含批量标注、组合筛选、词表管理、设置诊断、UI Automation、视觉细节和完整离线测试包。为避免重新形成臃肿页面和大而全任务中心，拆成独立纵向切片：

1. **Stage 5A：批量待入库效率**。资源管理器式多选、批量资料、批量处理排队和批量正式入库编排。
2. **Stage 5B：正式库管理效率**。组合筛选、正式资产多选和批量资料编辑。
3. **Stage 5C：管理与质量收口**。词表管理增强、设置诊断、完整 Windows UI Automation 和视觉收尾。

本规格只约束 Stage 5A。后续切片复用本阶段形成的选择与批量命令边界，但不能提前增加空页面、空按钮或通用批量任务平台。

## 3. 已确认的产品决策

1. 多选采用 Windows 资源管理器式交互：单击、`Ctrl` 多选、`Shift` 连选和 `Ctrl+A`。
2. `Ctrl+A` 选择当前搜索和状态筛选结果，包括滚动区域中未显示的匹配项目，不选择被筛选排除的项目。
3. 多选后顶部显示批量操作栏和选择数量；右侧详情栏切换为选择与状态汇总。
4. 批量资料使用独立原生对话框，按“追加 / 移除 / 替换”三个动作页面切换。
5. 作者和内容标签支持追加、移除和替换。
6. 系列只出现在“替换”页，可以替换为一个系列或明确清空。
7. “替换”页的每个资料字段默认“不修改”；必须单独启用，清空也必须显式选择。
8. 显示名称继续逐项编辑，不能批量设置相同显示名称。
9. 批量资料修改是整批原子提交。任何项目版本或状态失效时，整批不修改。
10. 批量工具栏提供独立“开始前置处理”，只为已识别出处理方案且允许排队的项目排队。
11. 批量正式入库先显示一次分类汇总确认，不逐项弹出普通确认窗口。
12. 批量正式入库采用分流执行。可执行项目继续；需要处理、存在冲突、恢复受阻或文件变化的项目保持原状态。
13. 批量执行不连续打开冲突窗口。冲突项目留在列表中，由用户稍后逐个处理。
14. 一个项目失败不回滚已经完成的其他项目，也不阻塞尚可安全执行的项目。
15. 批量入库运行时可以“停止后续操作”，但不为了停止批次而强制破坏当前单项的安全提交边界。

## 4. 范围

### 4.1 包含

- 待入库列表的 Extended Selection 和键盘选择语义。
- 多选状态、选择顺序和筛选范围管理。
- 顶部批量操作栏和右侧批量汇总。
- 按动作切换的批量资料原生对话框。
- 作者和标签的追加、移除、替换。
- 系列的替换和清空。
- 资料版本重新验证和原子批量提交。
- 通用批量前置处理排队。
- 批量正式入库预览、确认、串行分流执行、停止后续和结果汇总。
- 合并刷新和已有项目通知链适配。
- 新控件的稳定 `AutomationId` 和可访问名称。
- Stage 5A 自动化测试、离线 Windows x64 测试包、包级烟雾测试和人工验收清单。

### 4.2 不包含

- 批量设置显示名称或修改物理文件名。
- 批量冲突决策、自动替换目标或统一应用冲突策略。
- 批量恢复中心、批次历史页面或持久化批量任务状态机。
- 批量删除待入库文件或正式资产。
- 自动开始前置处理、自动正式入库或后台无人值守入库。
- 正式文件库的组合筛选和正式资产批量编辑。
- 词表管理增强和设置诊断。
- 完整 Windows UI Automation 驱动框架。
- Stage 6 的 Web 版切换、冻结或退役。

## 5. 架构

采用“Desktop 选择状态 + Application 批量编排 + 复用单项目服务”：

```text
InboxPage / InboxViewModel
        │  项目 ID、期望资料版本、用户动作
        ▼
Application
  ├─ BatchMetadataService
  ├─ BatchProcessingService
  └─ BatchIngestService
        │
        ├─ 资料编辑与持久化端口
        ├─ 现有 ProcessingCommandService
        ├─ 现有 IngestService / ConflictService
        └─ 现有通知、恢复和清理链
```

依赖方向不变：

```text
Desktop → Application → Domain
Desktop → Infrastructure → Application / Domain
```

Desktop 不包含：

- 文件系统路径选择和受控根判断；
- 哈希、大小和文件身份比较；
- 处理器类型或 MP4/M4A 判断；
- 冲突原因和允许动作推断；
- 文件提交、备份、恢复和清理规则；
- 批量资料事务边界。

Stage 5A 不新增 `Batch` 领域聚合。批量选择和进度是当前交互会话中的编排状态；单个媒体项目、处理任务、冲突案例和入库操作继续是持久化事实。

## 6. Desktop 交互

### 6.1 选择模型

待入库列表使用 Extended Selection：

- 普通单击只选择当前项目。
- `Ctrl` 单击添加或移除单个项目。
- `Shift` 选择上一个焦点锚点到当前项目的连续范围。
- `Ctrl+A` 选择当前查询结果中的全部项目。
- `Esc` 清空多选；关闭批量对话框只关闭对话框，不清空选择。

选择顺序以当前列表排序为准，用于批量处理和批量入库的可预测执行顺序。

搜索文本或状态筛选变化时清空选择，避免操作已经不可见的项目。普通扫描刷新时按照项目 ID 对选择做交集，只移除已经不存在或离开当前待入库查询的项目。列表重排后重新建立焦点锚点，不沿用旧索引。

### 6.2 单选和多选详情

- 选择 0 项：右侧保持现有空状态。
- 选择 1 项：右侧保持现有单项目预览、资料和操作。
- 选择 2 项及以上：右侧显示选择总数、图片/视频数量，以及可入库、需处理、存在冲突、恢复受阻和其他不可操作数量。

右侧批量汇总不提供资料输入控件。这样可以避免窄侧栏同时承担资料编辑、状态汇总、进度和提交按钮。

### 6.3 批量操作栏

多选时，中间内容区顶部显示：

- 已选择数量；
- “修改资料”；
- “开始前置处理”；
- “正式入库”；
- “取消选择”。

按钮的可用性由 Application 返回的允许动作汇总决定。Desktop 不通过卡片状态名称自行推断。

### 6.4 批量资料对话框

独立原生对话框顶部显示选择数量，内容使用三个动作页：

1. **追加**：追加作者和内容标签。
2. **移除**：移除作者和内容标签。
3. **替换**：分别启用作者、系列或内容标签，然后将启用字段替换为精确值。

“移除”页只列出选中项目中实际存在的词项，并显示覆盖数量，例如“作者甲 · 6/8”。不存在于某个项目的待移除词项对该项目是无变化，不是错误。

“替换”页中：

- 每个字段默认“不修改”；
- 启用作者后，可以替换为一个或多个作者，或明确清空全部作者；
- 启用系列后，只能选择一个系列或明确清空；
- 启用标签后，可以替换为一个或多个标签，或明确清空全部标签；
- 空白输入本身不代表清空。

追加和替换允许从词表选择已有名称，也允许创建符合现有词表规范的新名称。移除只引用已有词项标识，不根据自由文本猜测要删除的词项。

### 6.5 批量入库确认与进度

“正式入库”先打开一个汇总确认，显示：

- 可直接入库；
- 需要前置处理；
- 存在冲突；
- 恢复受阻；
- 文件变化或其他不可操作。

确认后只对执行时仍可入库的项目开始串行执行。进度显示“正在处理 3/12”和当前项目的安全显示名称或实际文件名；路径和哈希不显示。

执行过程中提供“停止后续操作”。该操作在当前项目结束后停止循环。用户正常关闭软件时，已有关闭协调器负责当前操作：已经完成的项目保持完成，执行中的项目由现有恢复状态接管，未开始项目保持原状态。

最终汇总显示完成、冲突、需要处理、失败或变化和用户停止数量。成功项目离开待入库列表，选择自动收缩到未完成项目，并提供“只显示未完成项目”。

## 7. 应用层契约

### 7.1 选择快照

所有批量命令接收不可变选择快照，至少包含：

- 待入库项目 ID；
- 资料版本；
- 用户选择时的列表顺序。

Desktop 不传递文件路径、SHA-256 或冲突目标路径。

### 7.2 BatchMetadataService

批量资料请求包含：

- 模式：`Add`、`Remove` 或 `Replace`；
- 选择快照；
- 作者和标签词项引用；
- 替换模式下每个字段的启用状态；
- 系列替换值或显式清空标记。

服务先完成全部验证并构建变更计划：

1. 所有项目存在且仍属于待入库范围。
2. 所有项目当前允许资料编辑。
3. 每个项目的资料版本与选择快照一致。
4. 词项引用和新名称符合词表规范。
5. 替换字段的“不修改 / 精确集合 / 明确清空”语义没有歧义。

验证通过后，持久化端口在一个数据库事务中应用全部变化。为避免 SQLite 参数或命令规模限制，内部可以分块读取和写入，但所有分块必须共享同一事务；任何失败都会回滚整个批量修改。

无实际变化的项目不增加资料版本。成功结果返回修改数量和无变化数量。

### 7.3 BatchProcessingService

批量处理服务按选择顺序逐项调用现有通用处理命令：

- 有有效处理方案且允许排队：进入现有队列；
- 已排队或正在处理：报告“已在队列”，不重复创建任务；
- 不需要或没有处理方案：报告“无需处理”；
- 输入变化、状态不允许或计划失效：报告“需要检查”。

批量服务不并行执行媒体工具。所有实际处理继续由现有单一 `ProcessingQueueWorker` 串行领取。处理器发现、计划、参数和验证仍由注册表及具体处理器负责。

### 7.4 BatchIngestService

批量入库分成两个应用用例：

1. **Preview**：按当前事实重新分类选择项，生成汇总 DTO 和允许确认的数量。
2. **Execute**：用户确认后按选择顺序串行调用现有单项目入库服务，并在每项开始前重新验证。

Preview 不是安全凭证。Execute 不相信旧分类，也不因 Preview 认为可入库就绕过输入、冲突或资料版本检查。

批量执行结果按项目归类：

- `Completed`；
- `RequiresProcessing`；
- `ConflictBlocked`；
- `RecoveryBlocked`；
- `ChangedOrInvalid`；
- `Failed`；
- `NotStarted`。

冲突结果只更新卡片和汇总，不从编排服务打开 Desktop 对话框。

## 8. 持久化与并发

Stage 5A 不新增批次表、批次任务表或批次历史表。

资料批量修改需要在持久化层增加一个明确的原子端口。实现必须：

- 在事务内重新读取并比较全部资料版本；
- 在同一事务内解析或创建作者、系列和标签词项；
- 对作者和标签保持稳定顺序和去重；
- 对系列保持零或一个的约束；
- 只更新实际发生变化的草稿；
- 任一并发冲突、约束失败或写入失败时回滚全部项目；
- 事务提交后才发布资料变化通知。

处理排队和正式入库不使用跨项目数据库事务。它们是多个可独立恢复的单项目操作，按项目返回部分结果。

## 9. 刷新、并发和命令门

批量资料提交期间：

- 对话框禁用重复提交；
- 扫描和其他通知可以继续到达，但提交依靠资料版本判断是否失效；
- 失败时保留用户输入，不自动基于新资料重试。

批量处理排队期间只串行创建或确认队列记录。队列创建完成后，项目级进度继续由现有通知链驱动。

批量入库在一个编排循环中串行发起，复用现有媒体运行门和项目级状态约束。界面对短时间内连续到达的项目通知进行合并刷新，避免每个项目多次重新查询整个列表；合并不得延迟安全状态持久化。

同一窗口同一时间只允许一个批量编排命令。单项目命令仍由 Application 的项目状态和并发版本拒绝不安全重入，不能只依赖按钮禁用。

## 10. 错误处理

### 10.1 批量资料

批量资料错误是整批失败，至少区分：

- 选择已失效；
- 资料版本变化；
- 项目当前不可编辑；
- 词项名称无效或冲突；
- 持久化失败。

界面显示可理解的错误类别和受影响数量。失败后保留对话框输入，但要求用户刷新或重新选择后再次确认，不自动重放旧命令。

### 10.2 批量处理与入库

批量处理和入库按项目返回结果，不因单个失败抛弃其他结果。意外的应用级失败停止尚未开始项目，并把它们标记为 `NotStarted`；已经持久化的单项目状态由现有恢复机制负责。

日志只记录批量相关 ID、选择数量、结果计数、阶段、耗时和稳定错误代码。不得记录完整路径、实际文件名、显示名称、作者、系列、标签、媒体 SHA-256、对话框内容或诊断令牌。

## 11. 包级诊断边界

Stage 4 已有包探针较大。Stage 5A 不继续把新场景直接堆入单个 Stage 4 探针类。实施时将通用的受控临时根、所有权令牌、固定样本校验、结果写入和清理逻辑提取为包探针基础设施，并把场景拆成独立模块：

- 既有 Stage 4 冲突与恢复场景；
- Stage 5A 批量资料、处理排队和批量入库场景。

正常软件启动仍不包含诊断 UI 或环境变量入口。探针只接受严格白名单参数、系统临时目录中的自有根、一次性所有权令牌和固定样本哈希。普通运行不使用这些入口。

在完整 UI Automation 到来前，Stage 5A 包探针验证发布二进制中的应用与基础设施批量闭环；多选键盘交互和对话框视觉行为由 Desktop 测试及人工验收覆盖。

## 12. 可访问性与自动化准备

本阶段新增或改变的控件必须提供稳定 `AutomationId` 和可访问名称，包括：

- 待入库列表；
- 批量操作栏；
- 修改资料、开始前置处理、正式入库和取消选择；
- 追加、移除、替换页；
- 每个字段的启用、清空和提交控件；
- 批量入库确认、进度、停止后续和结果汇总。

键盘焦点规则：

- 打开批量资料对话框时焦点进入当前动作页的第一个可编辑字段；
- 关闭对话框后焦点返回待入库列表；
- 多选后右侧汇总更新不抢夺列表焦点；
- 批量执行结束后焦点返回第一个未完成项目；没有未完成项目时返回列表标题。

本阶段不绑定某个桌面自动化工具的内部 API。Stage 5C 的驱动通过稳定 Automation 属性操作发布程序。

## 13. 测试设计

### 13.1 Domain 和 Application

- 追加、移除和替换动作的合法与非法组合。
- 替换字段的“不修改 / 精确集合 / 明确清空”。
- 作者和标签去重、顺序及不存在词项的移除无变化。
- 系列零或一个约束。
- 全部项目验证通过后才允许提交。
- 任一项目版本变化、状态失效或名称无效时整批失败。
- 无变化项目不增加资料版本。
- 批量处理的已排队、正在处理、无需处理和计划失效分类。
- 批量入库 Preview 与 Execute 重新验证。
- 串行顺序、部分成功、冲突不弹窗和停止后续语义。
- 意外编排失败时未开始项目标记正确。

### 13.2 Infrastructure 集成

使用真实 SQLite 和独立文件目录覆盖：

- 多项目资料更新在一个事务中提交。
- 中间分块写入失败时完整回滚。
- 事务内词项规范化、创建和复用。
- 并发资料版本变化导致完整回滚。
- 大数量选择不会触发 SQLite 参数限制或部分提交。
- 多种处理计划批量排队后仍由一个工作器串行执行。
- 普通媒体、处理输出、冲突、替换恢复和延迟清理回归。
- 批量入库关闭或中断后不丢失文件、不重复资产。
- 批量日志不包含敏感资料。

### 13.3 Desktop

- 单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc` 选择语义。
- `Ctrl+A` 只选择当前查询结果。
- 筛选改变清空选择；扫描刷新按 ID 收缩选择。
- 0、1、多选时右侧详情切换。
- 批量操作栏允许动作、数量和键盘焦点。
- 按动作切换的资料对话框和替换字段启用规则。
- 资料整批失败时保留输入。
- 入库确认分类、总体进度、停止后续和最终汇总。
- 冲突结果不触发连续对话框。
- 所有新控件的稳定 `AutomationId` 和可访问名称。

### 13.4 回归和包级烟雾

- Stage 4 验收时的 473 项测试作为最低回归基线，新增测试叠加其上。
- Release 构建必须为 0 警告、0 错误。
- 受限 `PATH` 离线启动、原生窗口、单实例、无浏览器和干净退出继续通过。
- 包探针使用多张图片、普通视频和同名 MP4/M4A 验证批量资料、通用处理排队、分流入库和冲突保留。
- 包探针和人工验收结束后无 TraceFold 或 FFmpeg 残留进程。

## 14. 人工验收

1. 使用鼠标单选、`Ctrl` 多选、`Shift` 连选和 `Ctrl+A` 当前筛选结果。
2. 改变搜索或状态筛选，确认旧选择被清空；扫描刷新只移除消失项目。
3. 分别执行作者/标签追加、移除和替换，以及系列替换和清空。
4. 在替换页不启用某字段，确认该字段在所有项目中保持不变。
5. 提交前让一个项目资料版本变化，确认整批不修改且输入仍保留。
6. 混选普通图片、普通视频、同名 MP4/M4A、冲突项和失败项。
7. 批量开始前置处理，确认只有适用项目排队，实际处理仍串行。
8. 批量正式入库确认只处理可执行项目，不连续打开冲突窗口。
9. 中途点击“停止后续操作”，确认当前项目安全结束，剩余项目保持未开始。
10. 批量执行中正常关闭并重启，确认无源文件丢失、重复资产或无法解释的正式文件。
11. 验证成功项目离开列表，冲突和异常项目保留选择并可逐项继续。
12. 解压 Stage 5A Windows x64 离线 ZIP，完成受限 `PATH` 本机烟雾和人工检查。

## 15. 验收标准

1. 资源管理器式选择和当前筛选范围语义稳定、可预测。
2. 多选不会使单项目右侧详情、预览和操作逻辑分叉或失效。
3. 作者和标签的追加、移除、替换，以及系列替换和清空符合明确语义。
4. 批量资料任一项目失效时全部回滚，不产生部分修改。
5. Desktop 和 ViewModel 不包含处理器类型、路径、哈希或冲突推断规则。
6. 批量处理只排队适用项目，继续使用现有单一串行处理工作器。
7. 批量入库复用现有单项目冲突、备份、恢复和清理状态机。
8. 冲突和失败不阻塞其他项目，也不会产生连续冲突弹窗。
9. 停止后续或关闭软件不会丢失文件、重复资产或创建无法归属的恢复内容。
10. 新控件具备稳定 Automation 属性，后续 UI Automation 无需重做控件边界。
11. 日志不泄露用户路径、文件名、资料、哈希或诊断令牌。
12. 完整自动化测试、Release 构建、离线包烟雾和本机人工验收通过。

## 17. 已知发布门槛

当前没有可用的干净 Windows 11 x64 虚拟机或另一台全新机器。本机受限 `PATH` 离线烟雾和人工验收不能替代“没有 SDK、开发工具和既有运行状态”的干净系统验证。该项继续作为正式发布门槛，不因 Stage 5A 本地通过而标记为完成。

## 18. 实施顺序约束

1. 先建立选择模型和批量资料契约，再连接 Desktop 批量操作栏。
2. 先让批量资料具备真实 SQLite 原子性，再开放提交按钮。
3. 先让批量处理只复用通用处理注册表和队列，再增加 Desktop 命令。
4. 先完成批量入库 Preview、Execute 和停止语义，再增加进度与汇总界面。
5. 先拆分包探针通用基础设施，再增加 Stage 5A 场景，不能继续扩大单个 Stage 4 探针类。
6. 所有应用和集成测试通过后才制作离线测试包。
7. 自动包级烟雾通过后再进入人工验收。

本规格没有遗留产品选择。实施中的类型和方法命名可以贴合现有代码，但不得削弱原子批量资料、通用处理器边界、单项目入库复用、冲突不自动决策和停止后续的安全语义。
