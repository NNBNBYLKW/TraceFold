# TraceFold 原生媒体桌面端 Stage 2 设计

- 日期：2026-08-22
- 状态：聊天设计已确认，待规格审阅
- 上位规格：`docs/superpowers/specs/2026-08-21-native-media-desktop-design.md`
- 前置检查点：`docs/media-desktop-stage1-acceptance.md`

## 1. 目标

Stage 2 在现有 WinUI 3 原生基础上实现第一个可日常使用的纵向切片：

> 立即刷新 → 选择文件 → 可选标注 → 正式入库

本阶段只处理无需前置处理且不存在冲突的普通图片和视频。它建立可扩展的扫描、候选分组、稳定性、资料、词表和单文件安全入库边界；Stage 3 在这些契约上增加处理器，Stage 4 增加完整冲突解决和高级恢复，不重写 Stage 2 主流程。

产品原则仍是方便管理文件。作者、系列、标签和显示名称均可选，不把正式入库变成强制填表。

## 2. 范围

### 2.1 包含

- 只扫描待入库目录第一层。
- 手动立即刷新。
- 可持久化的自动扫描开关，默认关闭；开启后每 5 秒扫描一次。
- 下载候选的短期后台稳定性复查。
- 图片格式：`.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`。
- 视频格式：`.mp4`、`.mov`、`.mkv`、`.webm`。
- 图片缩略图与右侧大图预览。
- 视频缩略图或通用图标，以及右侧原生视频播放。
- 显示名称、多作者、零或一个系列、多标签。
- 草稿自动保存。
- 作者、系列和标签共享词表。
- 单个普通文件的无冲突安全入库。
- 正式库浏览、基础名称搜索、预览和逻辑资料编辑。
- 同名或同内容冲突识别并阻止入库。
- 同名 MP4/M4A 识别为需要前置处理的单个待入库项。
- 单文件、无冲突入库所需的最小持久化操作记录和启动核对。
- 独立离线 ZIP 测试包。

扩展名匹配不区分大小写。

### 2.2 不包含

- MP4/M4A 合并或 FFmpeg、FFprobe。
- 冲突对比弹窗、跳过、两者都保留或替换。
- 批量选择、批量标注或批量入库。
- 作者、系列、标签和媒体类型的组合筛选。
- 正式资产物理重命名或删除。
- 递归扫描子文件夹。
- 对不支持格式的展示、移动、重命名或删除。
- 网络下载、联网识别、AI 标签或外部插件。
- 完整故障注入矩阵、替换备份和通用三阶段恢复；这些属于 Stage 4。

## 3. 已确认的产品决策

1. 冲突项只提示并阻止入库，源文件保持不动。
2. 待入库扫描不递归。
3. 支持格式沿用当前 Web 版的 5 种图片和 4 种视频格式。
4. 自动扫描默认关闭，用户可在设置中开启。
5. 手动刷新发现候选后，稳定性复查自动继续，不要求再次点击刷新。
6. 所有资料字段均可选。
7. 草稿停止输入约 500 毫秒后自动保存，入库前强制刷新保存。
8. 新作者、系列和标签可在资料面板中直接创建。
9. 同名 MP4/M4A 展示为需要前置处理的项目，Stage 2 禁止入库。
10. 采用可扩展纵向切片，不把扫描、EF Core 或文件移动逻辑放入 ViewModel。

## 4. 架构与职责

### 4.1 Domain

领域层增加以下概念：

- `InboxItem`：一个待入库工作单元。
- `SourceFile`：规范路径、扩展名、大小、最后修改时间、轻量指纹、完整哈希和存在状态。
- `MetadataDraft`：显示名称、作者、系列和标签草稿。
- `MediaAsset`：正式库中的逻辑资产。
- `Author`、`Series`、`Tag`：共享词表实体。
- `IngestOperation`：普通文件入库的持久化操作状态。

领域对象决定状态转换和允许动作。调用者不能通过直接写状态字符串绕过规则。

### 4.2 Application

应用层按用例拆分：

- 扫描待入库目录。
- 复查候选稳定性。
- 查询待入库列表和详情。
- 保存资料草稿。
- 查询与维护词表。
- 入库普通文件。
- 查询正式库。
- 编辑正式资产逻辑资料。
- 读取和修改自动扫描设置。
- 启动时核对未完成的普通入库操作。

应用层定义仓储、文件枚举、文件快照、哈希、受控存储、预览和时钟端口。它不引用 WinUI、EF Core、SQLite 或具体 Windows 文件 API。

### 4.3 Infrastructure

基础设施层实现：

- EF Core SQLite 仓储和迁移。
- 第一层目录枚举。
- 文件快照、SHA-256 和受控文件复制、移动、删除。
- 候选稳定性调度。
- 自动扫描调度。
- Windows 缩略图和预览缓存所需的基础设施。
- 普通入库操作的启动核对。

只有存储实现可以复制、移动或删除媒体文件。所有写操作必须验证目标位于已配置的待入库、正式库或工作目录内。

### 4.4 Desktop

桌面层实现待入库、正式库、词表和设置的页面及 ViewModel。ViewModel 只调用应用层用例，不能直接访问 DbContext、文件系统、哈希实现或进程 API。

右侧资料面板承载预览和编辑器。页面不复制领域状态机，只依据应用层返回的状态、提示和允许动作启用按钮。

## 5. 候选发现与分组契约

扫描器只枚举待入库目录第一层的普通文件，并将文件快照交给已注册的候选分类与分组规则。扫描器本身不包含 MP4/M4A 条件分支。

注册规则分为两类：

- 直接媒体规则：声明 Stage 2 支持的图片和视频扩展名。
- 伴随文件分组规则：声明主文件、伴随文件、分组键、观察宽限时间和所需处理能力。

MP4/M4A 规则以同一目录、忽略扩展名后文件名不区分大小写相同作为分组键。它声明 `.mp4` 为主文件、`.m4a` 为伴随文件，并返回“需要 mp4_m4a_merge 处理能力”。Stage 2 没有该能力，因此项目进入 `RequiresProcessing`。

扫描器可以枚举规则声明的伴随文件扩展名，但不会把单独的 M4A 建立为可直接入库媒体。这样既不会忽略已经存在的配对，也不会把格式逻辑写死在扫描主流程里。

## 6. 扫描、稳定性与幂等

### 6.1 手动与自动扫描

“立即刷新”调用幂等扫描用例。自动扫描使用同一用例，不建立第二条业务路径。

自动扫描设置保存在 SQLite 中：

- 默认值：关闭。
- 开启后的固定周期：5 秒。
- Stage 2 不提供周期调节项。

### 6.2 临时文件与不支持格式

以 `.part`、`.crdownload` 或 `.tmp` 结尾的文件被忽略。不属于直接媒体规则或伴随文件规则的文件也被忽略。

忽略表示不展示、不登记、不移动、不重命名、不删除。

扫描器只接受普通文件，忽略目录和重解析点。文件的最终规范路径必须仍位于待入库目录第一层；无法证明这一点的条目按路径错误记录，但不读取或操作目标内容。

### 6.3 稳定性

新候选立即以 `WaitingForStability` 显示。候选监视器只复查当前不稳定项目，不等同于持续扫描整个目录。

复查规则：

- 文件大小和最后修改时间构成轻量观察值。
- 两次观察至少间隔 2 秒。
- 连续两次观察值相同才视为稳定。
- 任一观察发生变化时重新计数。
- 监视器停止后，下一次手动或自动扫描可以重新激活候选。

分组规则可以声明伴随文件宽限时间。MP4/M4A 规则的宽限时间为首次发现 MP4 后最多 10 秒；宽限期内候选监视器同时检查同名 M4A。宽限期结束且没有 M4A时，稳定 MP4 可以作为普通视频进入 `ReadyToTag`。

### 6.4 幂等与源变化

- 同一规范路径和同一活动源身份反复扫描只更新现有记录。
- 已完成项目释放活动路径；之后同名新文件按新指纹建立新项目。
- 稳定后源文件变化会清除旧预览和完整哈希，退回 `WaitingForStability`。
- 源变化保留资料草稿，但显示明确警告。
- 源文件消失时项目进入 `SourceMissing`，不执行磁盘补救。
- 界面为仍然缺失且从未提交入库的项目提供显式“清除记录”；普通刷新不会自动删除其草稿。

## 7. Stage 2 状态与允许动作

Stage 2 使用以下可见状态：

```text
WaitingForStability
  → Analyzing
  → ReadyToTag
  → Ingesting
  → CleanupPending
  → Completed

Analyzing → RequiresProcessing
Ingesting → ConflictBlocked
任一分析或入库步骤 → Failed
稳定后源变化 → WaitingForStability
源文件消失 → SourceMissing
```

关键允许动作：

- `WaitingForStability`：可查看状态，不可入库。
- `ReadyToTag`：可预览、编辑草稿、正式入库。
- `RequiresProcessing`：可查看 MP4 预览和编辑草稿，不可入库。
- `ConflictBlocked`：可查看冲突原因和打开待入库目录，不提供冲突选择。
- `CleanupPending`：正式资产已存在，可重试安全清理。
- `Failed`：只在错误标记为可重试时显示重试。
- `SourceMissing`：不可入库，可在刷新时清除。

Stage 3 将 `RequiresProcessing` 接入处理计划和执行器；Stage 4 将 `ConflictBlocked` 接入原生冲突对比与选择。

`RequiresProcessing` 是对上位规格状态机的 Stage 2 细化。Stage 3 接入后，路径扩展为 `Analyzing → RequiresProcessing → Processing`。项目进入 `Completed` 后从活动待入库列表移除，并立即出现在正式库查询结果中。

## 8. 资料草稿与共享词表

### 8.1 资料规则

- 显示名称可空；为空时界面回退到实际文件名。
- 一个项目可关联多位作者。
- 一个项目可关联零或一个系列。
- 一个项目可关联多个标签。
- 同一项目内作者和标签自动去重。
- 编辑显示名称永远不修改实际文件名。

作者、系列和标签使用独立实体及关系表，不存成逗号文本或 JSON。

### 8.2 名称规范化

词条输入先去除首尾空白，再使用 Unicode 兼容规范化和不区分大小写的规范键判重。规范键唯一，展示名称保留首次创建时的形式。空白名称和规范化后为空的名称被拒绝。

重命名后的规范键若已被同类词条占用，则拒绝重命名并提示用户；Stage 2 不自动合并引用。

### 8.3 自动保存

资料编辑停止约 500 毫秒后触发保存。以下操作必须先刷新尚未提交的草稿：

- 切换选择。
- 切换页面。
- 点击正式入库。
- 关闭主窗口。

每次保存带草稿版本。仓储只接受不早于当前版本的写入，防止较慢的旧请求覆盖较新的用户输入。

### 8.4 词表维护

资料面板提供建议列表；用户输入不存在的词条并按 Enter 时直接创建并选中。

词表页支持：

- 搜索。
- 新建。
- 重命名。
- 显示草稿和正式资产的引用数量。
- 删除未被引用的词条。

被任何草稿或正式资产引用的词条不能直接删除。Stage 2 不实现词条合并。

### 8.5 正式资料编辑

正式资产复用相同的资料编辑器和关系约束。更新只修改 SQLite 中的逻辑资料，不修改、移动或重命名正式媒体文件。

## 9. 普通文件安全入库

### 9.1 前置条件

只有同时满足以下条件时才允许入库：

- 项目状态为 `ReadyToTag`。
- 目录配置有效。
- 源文件存在并与最后稳定快照一致。
- 入库前重新运行候选分组规则，确认没有晚到的伴随文件或新的前置处理要求。
- 当前项目没有其他入库操作运行。
- 最新资料草稿已经保存。

### 9.2 冲突检测

入库在后台计算源文件完整 SHA-256，并再次核对大小和修改时间。

以下情况进入 `ConflictBlocked`：

- 正式目录目标文件名已经存在，不论是否登记在数据库。
- 数据库中已有相同实际文件名。
- 数据库中已有相同完整 SHA-256，即使实际文件名不同。

Stage 2 不为正式库中未登记且不同名的所有文件预先计算哈希。此类文件只在目标名称相同时形成文件系统冲突。

冲突发生前不复制或删除源文件。冲突项保留草稿和源文件。

### 9.3 持久化操作状态

无冲突后先创建 `IngestOperation`，记录操作标识、项目、源快照、目标文件名、完整哈希、资料快照和当前阶段。

普通入库操作状态为：

```text
Created
  → Staged
  → FileCommitted
  → DatabaseCommitted
  → CleanupPending
  → Completed
```

任一阶段可进入 `Failed`，但失败不能触发对唯一源文件的提前删除。

### 9.4 暂存与文件提交

1. 将源文件复制到工作目录中以操作标识隔离的暂存目录。
2. 验证暂存文件大小和 SHA-256。
3. 如果工作目录与正式库在同一卷，存储实现可以使用同卷移动提交。
4. 如果不在同一卷，先复制到正式库内受控的目标侧临时文件，验证后在正式库内原子改名为目标文件。
5. 任何目标侧临时名称都包含操作标识，且不能作为正式资产展示。

提交前再次确认目标名称不存在。发现竞态冲突时保留源文件并进入 `ConflictBlocked`。

### 9.5 数据库提交与源清理

正式文件到位后，在单个 SQLite 事务中创建 `MediaAsset`、写入资料关系、完成 `InboxItem` 并把操作标记为 `DatabaseCommitted`。

事务提交后重新核对正式文件路径、大小和哈希。核对成功才允许删除待入库源文件。

删除规则：

- 删除前再次验证源规范路径和完整哈希。
- 源文件已变化时绝不删除，操作进入需要人工关注的清理失败状态。
- 删除成功后清除工作暂存和目标侧临时文件，操作进入 `Completed`。
- 删除失败时正式资产保持有效，操作停在 `CleanupPending`，源文件保留并可安全重试。

### 9.6 最小启动核对

Stage 2 只恢复单文件、无冲突入库：

- `Created` 或 `Staged`：源文件仍在时清除不完整暂存并允许重试。
- `FileCommitted`：按操作标识、目标路径和哈希核对；可证明一致时完成数据库提交，否则保留源文件并标记恢复失败。
- `DatabaseCommitted` 或 `CleanupPending`：验证正式资产后重试源清理。
- 无法证明文件身份时不删除任何文件，并向用户显示恢复错误。

Stage 4 在此记录上增加故障注入、替换备份、冲突选择和通用恢复状态。

## 10. 预览

图片使用原生图片控件。视频使用 WinUI 媒体播放器。图库优先显示系统或缓存缩略图，无法取得缩略图时使用图片或视频通用图标。

预览请求只接受数据库中的项目或资产标识，由应用层解析受控源，不能接受界面传入的任意绝对路径。

预览失败：

- 在右侧面板显示明确原因和通用图标。
- 不把预览失败等同于文件丢失。
- 不阻止状态为 `ReadyToTag` 的普通文件入库。
- 入库仍执行完整哈希和安全文件提交。

Stage 2 不使用 FFmpeg 生成视频缩略图或探测流。

## 11. 界面设计

### 11.1 待入库

顶部工具栏包含：

- 实际文件名或显示名称搜索。
- 状态筛选。
- “立即刷新”按钮。
- 最近一次扫描时间与结果。

中间内容区使用缩略图网格。卡片显示缩略图或通用图标、实际文件名和状态。Stage 2 只支持单选。

右侧资料面板显示：

- 大图或视频播放器。
- 实际文件名和文件状态。
- 显示名称。
- 作者多选。
- 系列单选。
- 标签多选。
- 当前主操作。

状态直接显示在卡片和右侧面板，不增加任务中心。

普通文件完成入库后，其卡片从待入库页移除，选择自动清空；新正式资产出现在正式库页，不自动切换当前页面。

### 11.2 正式库

正式库复用缩略图网格，支持按实际文件名或显示名称搜索。右侧面板支持预览、逻辑资料编辑和“打开所在目录”。

“打开所在目录”只接受已登记资产标识。Stage 2 不提供物理重命名、资产删除、组合筛选或批量操作。

### 11.3 词表

作者、系列和标签分为三个区域。每个区域提供搜索、新建、重命名、引用数量和受约束删除。

### 11.4 设置

在现有三个目录设置之外增加：

- 自动扫描开关，默认关闭。
- 最近一次扫描时间。
- 最近一次扫描结果。

Stage 2 不提供扫描周期输入框。

## 12. 并发、关闭与错误

- 扫描用例有单实例门闩；手动和自动触发重叠时共享同一轮结果。
- 每个待入库项目只有一个活动入库操作。
- 不同普通项目可以排队处理；Stage 2 默认串行执行文件提交，降低磁盘争用和恢复复杂度。
- 哈希、复制、缩略图和视频加载不阻塞 UI 线程。
- 关闭窗口后停止接受新扫描和入库，刷新待保存草稿，并让文件操作到达记录明确的安全点。
- 启动恢复完成前允许浏览，但禁用新的正式入库。
- 目录未配置或验证失效时禁用手动和自动扫描；自动扫描设置保持不变，目录恢复有效后再继续。
- 一个项目失败不阻止其他项目扫描、标注或入库。

用户可恢复问题显示在卡片或资料面板；应用级故障显示顶部通知并写日志。

日志包含时间、错误代码、操作关联标识、受控路径和状态，不记录图片、视频内容或用户填写的标签正文。

## 13. 数据库迁移

Stage 2 在 Stage 1 空业务数据库上增加：

- 待入库项目与源文件。
- 草稿。
- 作者、系列、标签及关系表。
- 正式资产及关系表。
- 普通入库操作。
- 自动扫描设置和最近扫描结果。

迁移必须保留 Stage 1 已保存的三个目录。新表和新字段使用安全默认值；自动扫描默认关闭。

数据库唯一约束至少覆盖：

- 活动源身份。
- 正式资产规范相对路径。
- 正式资产完整哈希。
- 各词表规范名称。
- 一个项目同一时刻只有一个活动入库操作。

## 14. 测试策略

### 14.1 Domain

- 多作者、单系列、多标签。

### 14.2 Application

- 重复入库命令只产生一个操作。
- 同名和同哈希冲突均阻止入库。
- 一个项目失败不阻塞其他项目。

### 14.3 Infrastructure

测试使用临时 SQLite、临时待入库目录、临时正式库和临时工作目录：

- EF Core 迁移保留 Stage 1 设置。
- 第一层扫描且不递归。
- 临时文件与不支持格式保持不变。
- SHA-256、同卷提交和跨卷安全路径。
- 暂存验证、数据库提交、源清理和清理重试。
- 各持久化阶段的启动核对。
- 所有路径逃逸均被拒绝。
- 测试清理失败时保留唯一源文件。

自动测试绝不读取、移动或删除用户设置中的真实目录。

### 14.4 Desktop

- 列表加载和选择。
- 状态筛选和基础搜索。
- 资料编辑及自动保存。
- 新词条创建和已有词条选择。
- 入库按钮的允许状态。
- 冲突、需要处理、源缺失和预览失败提示。
- 正式资料编辑不修改实际文件名。

### 14.5 发布与冒烟

离线 ZIP 不包含 Python、Node.js、浏览器或 FFmpeg。冒烟测试覆盖：

- 原生窗口和单实例。
- 离线启动。
- 临时测试目录扫描。
- 候选稳定。
- 普通文件入库。
- 正常关闭且无残留进程。

冒烟脚本只操作自己创建并验证归属的临时目录。

## 15. 手工验收

1. 配置三个专用测试目录，不使用 Web 版正在操作的目录。
2. 放入支持格式的图片和视频副本。
3. 点击“立即刷新”，每个文件只出现一次。
4. 验证“等待下载完成”自动变为“可标注”。
5. 填写多作者、单系列、多标签和显示名称，重启后草稿仍存在。
6. 正式入库普通图片和视频。
7. 确认源文件离开待入库目录，正式文件名保持不变。
8. 在正式库修改显示名称，确认物理文件名保持不变。
9. 放入同名 MP4/M4A，确认显示为需要前置处理且不能入库。
10. 制造同名或同内容冲突，确认源文件保留且不能入库。
11. 放入损坏或不可预览文件，确认不影响其他项目。
12. 关闭主窗口，确认客户端无残留进程。

本阶段生成新的离线 ZIP。当前没有虚拟机或 Windows Sandbox，因此干净 Windows 11 x64、无开发工具客体测试继续记录为“未执行”。当前主机的自动验证和专用测试目录手工验收可以作为 Stage 2 本地检查点，但不能作为干净客体通过的证明。

## 16. 完成标准

Stage 2 完成必须同时满足：

1. 所有新增自动化测试通过，Release 构建为 0 警告、0 错误。
2. 支持格式只扫描第一层，临时文件和其他格式保持原样。
3. 手动刷新、候选稳定性复查和可选自动扫描行为符合本规格。
4. 草稿、词表和正式资料编辑在重启后保持一致。
5. 普通文件无冲突入库后位于正式目录，实际文件名不变。
6. 正式提交验证完成前不删除待入库源文件。
7. 同名、同内容和 MP4/M4A 项均不会绕过阻止规则。
8. 异常只影响对应项目，关闭程序后无后台进程残留。
9. 提供可启动的 Windows 11 x64 离线 ZIP 和如实填写的验收记录。

## 17. 后续阶段接口

- Stage 3 注册处理器能力，消费 `RequiresProcessing` 项，并将验证输出交回现有入库用例。
- Stage 4 为 `ConflictBlocked` 提供预览对比和三种选择，扩展 `IngestOperation` 支持替换备份及完整恢复。
- Stage 5 在现有资料关系和查询端口上增加批量编辑、组合筛选、UI Automation 和视觉收尾。

Stage 2 不为这些后续功能提前增加页面或空按钮，只提供已经被当前纵向切片实际使用的契约和数据结构。
