## 1. 目标

Stage 5C-A 将现有只能搜索、新建、重命名和单项删除的词表页扩展为安全、清晰的词表维护工作区。用户可以主动发现重复或未使用词条，预览影响后显式合并或批量删除，并在当前软件会话内撤销最近一次词表维护操作。

本阶段建立以下主路径：

```text
选择作者 / 系列 / 内容标签
  → 搜索、引用状态筛选和排序
  → 资源管理器式选择词条
  → 查看引用和受影响文件
  → 合并到现有目标，或删除全部未使用词条
  → SQLite 原子提交
  → 可选：撤销最近一次词表维护操作
```

词表管理只改变 SQLite 中的词条和资料关联。它不得移动、重命名、删除或改写图片、视频及其他实际文件。

## 2. Stage 5C 边界

Stage 5C 是“管理与质量收口”阶段，继续拆成可独立实现和验收的纵向切片：

1. **Stage 5C-A：词表管理增强**。本规格覆盖三栏词表页、引用查询、显式合并、安全批量删除和会话内撤销。
2. **后续切片：设置诊断**。不属于本规格。
3. **后续切片：视觉与 Windows UI Automation 收口**。本规格只为新增词表控件提供稳定自动化边界，不在本切片实现整套发布级 UI Automation 驱动。

Stage 5C-A 延续 Stage 2 的共享词表模型和 Stage 5B 的版本化原子事务经验，但不复用 Stage 5A/5B 的通用批量编辑界面，也不建立持久化维护任务、后台队列或万能批量平台。

## 3. 已确认的产品决策

1. 重复词条必须由用户显式合并，软件不能因名称相似而自动处理。
2. 一次合并可包含多个源词条和一个目标词条；源与目标必须属于同一种词表类型。
3. 合并保留用户选定的现有目标词条 ID，并可在同一操作中选择最终显示名称。
4. 目标既可以是当前选择中的词条，也可以通过搜索选择另一个同类现有词条。
5. 合并前必须显示目标、全部源词条、受影响文件数量和逐项文件明细。
6. 普通重命名发生名称冲突时提示“名称已存在”，并提供进入预填合并流程的入口；不能自动合并。
7. 未使用词条通过用户主动选择“未使用”筛选发现，不自动清理。
8. 批量删除必须先多选、预览并确认；选择中只要存在一个已引用词条，整批删除就被阻止。
9. 合并和批量删除共享一个“最近一次词表维护操作”会话撤销位；新操作替换旧回执。
10. 撤销是全有或全无。相关资料或词条已变化时，整次撤销失效，不能部分恢复。
11. 词表页采用资源管理器式三栏布局；合并使用大型原生对话框。
12. 重复发现首版只提供名称搜索、引用状态筛选和排序，不提供模糊匹配、相似度提示或自动候选组。
13. 图片和视频遵循完全相同的词表维护规则。

## 4. 范围

### 4.1 包含

- 作者、系列和内容标签的管理查询与引用数量分解。
- 名称搜索、全部/已引用/未使用筛选、名称/引用数量排序。
- 词条列表的单选、`Ctrl` 多选、`Shift` 连选、`Ctrl+A` 和 `Esc`。
- 0 项、1 项和多项选择对应的右侧详情与动作状态。
- 现有新建、重命名和未引用删除能力在新布局中的保留。
- 多源词条到一个现有目标词条的显式合并。
- 合并目标搜索、可选最终名称、影响预览和确认对话框。
- 未使用词条的原子批量删除。
- 最近一次合并或批量删除的会话内撤销。
- 待入库资料草稿与正式资产资料关联的同步迁移。
- 受影响资料版本更新、变化通知和现有编辑器的陈旧写入保护。
- 稳定错误代码、隐私安全日志、可访问名称和 `AutomationId`。
- 自动化测试、包级探针、离线 Windows x64 测试包和人工验收清单。

### 4.2 不包含

- 修改物理文件名、扩展名、目录、媒体内容或缩略图文件。
- 跨作者、系列和内容标签类型的合并。
- 新建一个词条作为合并目标；目标必须已经存在。
- 模糊搜索、拼写纠正、相似度评分、自动重复推荐或自动合并。
- 自动清理、定时清理、启动时清理或后台维护任务。
- 删除已引用词条并同时删除文件资料引用。
- 持久化撤销历史、多个撤销层级、维护历史页或数据库操作日志表。
- 将 Stage 5A/5B 批量编辑抽象为跨页面万能批量框架。
- 设置诊断、完整发布级 Windows UI Automation 和整体视觉收尾。

## 5. 架构

采用“Desktop 页面状态 + Application 管理用例 + Infrastructure 原子持久化”的既有依赖方向：

```text
TaxonomyPage / TaxonomyViewModel
  ├─ 类型、搜索、筛选、排序和资源管理器式选择
  ├─ 单项 / 多项详情和动作门
  ├─ TaxonomyMergeDialog
  └─ 会话撤销提示条
          │
          ▼
Application
  ├─ TaxonomyManagementQueryService
  ├─ TaxonomyMergePreviewBuilder（纯内存）
  └─ TaxonomyMaintenanceService（命令编排与单次撤销）
          │
          ▼
Infrastructure
  ├─ EF / SQLite 管理查询
  ├─ 合并与批量删除事务
  ├─ 原子撤销事务
  └─ 提交后的合并变化通知
```

依赖保持：

```text
Desktop → Application → Domain
Desktop → Infrastructure → Application / Domain
```

Desktop 不直接访问 `DbContext`、关系表或 SQL。Application 不引用 WinUI，也不接触磁盘文件。Infrastructure 不持有页面选择、对话框输入或会话提示条状态。

现有 `ITaxonomySearchService` 和 `ITaxonomyService` 继续服务资料选择器及基本新建/重命名。管理页新增窄边界：

- 管理查询只负责返回词条、引用分解和确定排序；
- 合并预览构建器只把不可变准备快照转换为用户可见的前后差异；
- 维护服务只编排合并、批量删除、撤销、日志和通知；
- 维护仓储只负责在一个 SQLite 事务中重新验证和写入。

本阶段不新增持久化撤销表或维护任务表。预计不需要数据库结构迁移；会话撤销数据只保存在进程内存中。

## 6. 数据和应用层契约

### 6.1 管理查询

管理查询条件是不可变对象，至少包含：

- 一个 `TaxonomyKind`；
- 可空名称搜索文本；
- 引用状态：全部、已引用或未使用；
- 排序字段：显示名称或引用数量；
- 排序方向。

管理结果至少包含：

- 词条 ID、类型、显示名称和规范名称；
- 待入库草稿引用数；
- 正式资产引用数；
- 两者相加的总引用数。

引用数按资料所有者计数，而不是按查询联接后的重复行计数。同一个待入库项目或正式资产对同一词条最多贡献一次引用。

### 6.2 合并准备快照

合并准备结果是不可变快照，至少包含：

- 操作 ID 和词表类型；
- 目标词条的 ID、显示/规范名称和更新时间证据；
- 每个源词条的同类证据；
- 每个受影响资料所有者的类型、ID、当前资料版本；
- 受影响所有者的现有作者、系列、标签和稳定 ordinal；
- 用于预览的用户可见文件名称和待入库/正式库位置标识。

快照不包含物理文件写入命令。文件路径、哈希和媒体内容不属于合并契约。

### 6.3 维护命令与结果

合并命令包含准备快照身份、一个现有目标 ID、一个或多个不同的源 ID，以及可空最终显示名称。批量删除命令包含所选词条快照。所有集合拒绝空 ID、重复 ID、跨类型成员和目标仍出现在最终源集合中的情况。

维护结果返回成功状态、受影响待入库项目数、受影响正式资产数、删除词条数、是否可以撤销和稳定错误代码。用户名称、文件名或资料值不进入结果日志字段。

## 7. 三栏页面与查询交互

### 7.1 左栏：词表类型

左栏固定显示作者、系列和内容标签。每项显示总词条数，并可附带未使用数量。切换类型会清空搜索结果选择、关闭旧类型详情，并加载新类型查询；不允许跨类型保留选择。

### 7.2 中栏：词条列表

中栏顶部包含：

- 搜索框；
- 引用状态筛选；
- 名称/引用数量排序及方向；
- 新建词条入口；
- 立即刷新入口。

搜索只做名称子串匹配，并沿用现有 `%`、`_` 和转义字符的安全处理。查询和筛选由 SQLite 完成，不先加载全部词条再在 Desktop 过滤。排序必须具有稳定次级键，最终以词条 ID 保证确定顺序。

搜索文本或引用状态筛选发生实际变化时清空当前选择并给出非阻塞提示。只改变排序时按词条 ID 保留仍存在的选择，并重建 `Shift` 选择锚点。

词条列表使用资源管理器式 Extended Selection：

- 普通单击只选择当前词条；
- `Ctrl` 单击添加或移除；
- `Shift` 从焦点锚点连续选择；
- `Ctrl+A` 选择当前查询结果；
- `Esc` 清空选择。

### 7.3 右栏：上下文详情

- 0 项：显示“选择词条以查看引用和维护操作”。
- 1 项：显示名称、类型、待入库引用数、正式库引用数、重命名、合并和删除动作。
- 多项：显示选择数量、总引用、来源分解、合并入口和批量删除入口，并列出删除阻塞词条。

只要选择中有一个词条仍被引用，删除按钮就在界面上禁用并说明阻塞原因；应用层和仓储仍必须再次验证，不能把按钮状态当作安全边界。

## 8. 合并对话框

合并使用大型原生对话框，而不是右栏内嵌编辑或独立维护页面。对话框顶部明确显示“只修改软件资料，不修改实际文件”。

### 8.1 源与目标

对话框左侧列出全部源词条，右侧选择一个现有同类目标：

- 如果目标来自当前选择，目标自动从源集合移除，其余选中项成为源；
- 如果目标来自搜索结果之外，全部当前选中项成为源；
- 目标搜索只返回同一种 `TaxonomyKind`；
- 最终必须至少有一个源，并且目标与每个源 ID 不同。

只选择一个词条时也可以打开合并对话框，再通过搜索指定另一个目标。

### 8.2 最终名称

默认保留目标词条当前显示名称。用户可以在同一次合并中输入最终显示名称，名称继续使用 `TaxonomyName.Create` 的去空白、Unicode 兼容规范化和同类不区分大小写唯一规则。

最终规范名称与某个将被删除的源词条相同是合法的；事务先迁移引用并删除源，再更新目标名称。最终规范名称若被源集合和目标之外的第三个同类词条占用，则阻止操作，并要求将该词条改选为目标。

普通重命名遇到同类规范名称冲突时保持输入，显示冲突词条，并提供“改为合并”动作。该动作以当前词条为源、冲突词条为目标打开同一个合并对话框。

### 8.3 影响预览

预览必须显示：

- 目标词条及可选最终名称；
- 全部源词条；
- 去重后的受影响文件总数；
- 待入库项目数和正式资产数；
- 每个受影响文件的待入库/正式库标识、显示名称或实际文件名回退；
- 该文件当前相关词条与合并后的结果。

同一文件同时引用多个源词条时在受影响总数中只计一次。预览按资料所有者类型、用户可见名称和稳定 ID 确定排序。确认按钮只在快照完整、目标合法、名称合法且至少有一个源时启用。

## 9. 引用迁移规则

共享词表同时被待入库资料草稿和正式资产引用。合并必须迁移两类关系，否则不能删除源词条。

### 9.1 作者和内容标签

对每个受影响资料所有者独立处理：

1. 如果目标已经存在，保留目标当前 ordinal，移除所有源词条关系。
2. 如果目标不存在，用目标替换 ordinal 最小的源词条位置，再移除其余源词条关系。
3. 所有未参与合并的词条保持相对顺序。
4. 完成后去重，并将 ordinal 稠密重排为 `0..n-1`。

该规则同时适用于 `inbox_draft_authors`、`inbox_draft_tags`、`media_asset_authors` 和 `media_asset_tags`，保证预览和执行结果一致。

### 9.2 系列

一个资料所有者最多有一个系列。当前系列属于源集合时替换为目标；已经是目标或不属于源集合时不改变。合并永远不能产生多系列状态。

### 9.3 资料版本

每个实际发生关联变化的待入库草稿 `Version` 增加一次，每个实际发生关联变化的正式资产 `MetadataVersion` 增加一次，并更新对应资料更新时间。一个所有者即使引用多个源词条也只能增版一次。

目标仅重命名但某个所有者的关联 ID 未变化时，该所有者无需增加资料版本；词条查询和页面仍通过词表变化通知刷新显示名称。

## 10. 原子合并与并发验证

用户确认时，Infrastructure 在一个 SQLite 事务内：

1. 重新读取目标、全部源词条及其名称证据；
2. 验证同类、ID 完整、目标/源互斥和最终名称唯一性；
3. 重新读取全部源词条引用、稳定 ordinal 和资料版本；
4. 将当前状态与用户确认的准备快照比较；
5. 捕获撤销所需的源词条、目标旧名称和原始关联；
6. 按第 9 节规则迁移待入库与正式库引用；
7. 为实际变化的资料所有者各增加一次版本；
8. 删除全部源词条，并按需更新目标名称；
9. 保存撤销回执并提交事务；
10. 提交后发布一次合并变化通知并刷新词表页。

任何词条缺失、名称变化、引用新增/删除、ordinal 变化、资料版本变化、第三方名称冲突或数据库错误都使整个操作回滚，并返回“预览已过期”或更具体的稳定错误。系统不能基于新状态自动重放旧确认；用户必须刷新预览后再次确认。

对大引用集合可以分块读取和写入，但全部分块必须共享同一个事务。合并不写物理文件，因此不需要文件系统恢复状态机。

## 11. 未使用筛选与批量删除

“未使用”表示该词条在待入库草稿和正式资产中的总引用数都为零。用户在该筛选下多选词条，右栏显示待删除名称和数量，再打开确认预览。

删除命令同样允许从“全部”结果中发起，但选择中只要混入一个已引用词条，整批操作就被阻止并列出所有阻塞词条及其引用数。不能自动跳过阻塞项，不能部分删除，也不能为了删除词条而移除文件资料。

提交时在一个 SQLite 事务内重新读取全部词条并计算引用数。任一词条缺失、类型不一致、名称证据变化或引用数不再为零，整批删除零修改。成功后删除全部选中词条并生成一份撤销回执。单个未使用词条的删除也走同一批量删除用例，因此同样可撤销。

## 12. 最近一次词表维护撤销

`TaxonomyMaintenanceService` 在当前进程内存中保存至多一份回执。合并与批量删除共享这个撤销位：

- 成功合并用新的合并回执替换旧回执；
- 成功单项或批量未使用删除用新的删除回执替换旧回执；
- 成功新建或普通重命名会使旧维护回执失效，但不产生新回执；
- 操作失败且数据库零修改时不无故丢弃仍然安全的旧回执；
- 软件关闭后回执自然消失。

合并回执包含目标旧名称、被删除源词条的稳定身份和名称、每个受影响资料所有者的原始关联/ordinal，以及提交后的期望资料版本。删除回执包含被删除未使用词条的稳定身份、类型和名称证据。

撤销在一个 SQLite 事务内先验证：

- 目标仍存在且保持合并后的期望名称；
- 源词条 ID 仍不存在，待恢复规范名称未被无关词条占用；
- 全部受影响资料所有者仍存在并处于回执记录的提交后版本；
- 当前关联仍等于合并后的预期状态；
- 删除撤销中的词条 ID 和规范名称仍可安全恢复。

全部通过后，合并撤销恢复源词条、目标旧名称和每个所有者的原始关联/ordinal；删除撤销恢复被删除词条。恢复关联的资料所有者再次增加一次版本，不能把版本号倒退到历史值。任何验证失败都拒绝整个撤销并使冲突回执失效；数据库瞬时写入失败且事务已完整回滚时可以保留回执供重试。

词表维护通知携带受影响的待入库项目和正式资产 ID。现有正式库批量撤销若涉及这些资产必须失效；反过来，相关资料后续被单项或批量编辑时，词表撤销通过通知或最终版本验证失效。通知是及时更新 UI 的机制，事务内版本和关联验证才是最终安全边界。

## 13. 页面刷新与命令门

同一窗口同一时间只允许一个词表写命令或撤销运行。加载、预览和写入期间禁用重复提交，但不能以按钮状态替代数据库验证。

成功合并、删除或撤销后：

- 当前词表类型、搜索、筛选和排序保持不变；
- 列表执行一次合并刷新；
- 已删除源词条从选择中移除；
- 仍匹配查询的目标词条保持选中；
- 右栏重新加载引用分解；
- 待入库页和正式库页收到一次变化通知并刷新受影响资料；
- 页面显示成功数量和撤销入口。

失败时保留当前选择、合并目标、最终名称、对话框滚动位置和预览内容。用户可以按提示刷新预览或修改目标，不需要重新建立整个操作。

普通查询使用取消或串行门，较慢的旧搜索结果不能覆盖较新的搜索、类型或筛选条件。页面离开后完成的查询不能更新已销毁视图。

## 14. 错误处理

应用层至少区分以下稳定错误类别：

- 选择为空、重复或已经失效；
- 源/目标相同、跨类型或源集合为空；
- 源词条、目标词条或资料所有者缺失；
- 词条名称无效或与第三个词条冲突；
- 准备快照、引用集合、ordinal 或资料版本已过期；
- 批量删除包含已引用词条；
- 数据库约束或持久化失败；
- 撤销不存在、已经失效、名称冲突、关联冲突或版本冲突。

Desktop 将错误代码映射为简洁中文提示。可安全修改的错误保持对话框打开并保留输入；预览过期提示用户刷新；删除阻塞显示全部阻塞词条；未知错误显示可重试提示。任何错误都不能导致软件闪退或留下部分修改。

## 15. 隐私日志

维护服务为每个命令生成内存操作 ID，并记录开始、结束和失败阶段。结构化日志只能包含：

- 操作 ID；
- 词表类型；
- 源词条数量、删除词条数量；
- 受影响待入库项目数和正式资产数；
- 阶段、耗时、成功状态和稳定错误代码。

日志不得包含词条显示/规范名称、文件名、显示名称、文件路径、作者、系列、内容标签、哈希、对话框输入或逐项预览内容。异常对象在已知数据库错误路径上也不能通过消息或参数泄露这些值。

## 16. 可访问性与自动化准备

新增或变化的控件必须具有稳定 `AutomationId` 和中文可访问名称，包括：

- 作者、系列、内容标签类型项及数量；
- 搜索、引用状态筛选、排序字段、方向、新建和刷新；
- Extended Selection 词条列表；
- 单项/多项详情、引用分解、重命名、合并和删除；
- 合并对话框、源列表、目标搜索/结果、最终名称；
- 影响摘要、受影响文件列表、取消和确认；
- 删除阻塞列表、批量删除确认；
- 成功提示条和撤销按钮。

键盘焦点规则：

- 打开合并对话框后进入目标搜索；
- 目标已预填时进入最终名称或影响列表；
- 验证错误把焦点移动到对应输入或第一个冲突项；
- 关闭对话框后回到原词条选择；
- 合并、删除或撤销刷新后不抢夺正在使用的搜索框焦点；
- `Ctrl`、`Shift`、`Ctrl+A` 和 `Esc` 与正式库的资源管理器式选择保持一致。

## 17. 测试设计

### 17.1 Domain 和 Application

- 管理查询条件、筛选枚举和排序契约验证。
- 源/目标同类、ID 去重、目标互斥和至少一个源。
- 目标来自选择内和选择外两条路径。
- 最终名称为空、规范化、源名称复用和第三方冲突。
- 作者/标签目标已存在和不存在时的 ordinal 迁移。
- 多个源同属一个所有者时去重、保序和稠密重排。
- 系列替换及“一份资料最多一个系列”。
- 受影响所有者去重和预览前后结果。
- 每个待入库草稿和正式资产只增版一次。
- 混合删除选择整体拒绝，全部未使用才允许。
- 合并/删除共享单次撤销、替换、失效和关闭语义。
- 撤销恢复稳定词条 ID、目标名称和精确关联顺序，资料版本只前进不倒退。
- 失败后保留旧安全回执，冲突回执失效。

### 17.2 Infrastructure 集成

使用真实 SQLite 覆盖：

- 名称搜索、引用状态和排序在数据库侧组合执行。
- 引用数量正确分解待入库草稿与正式资产。
- 同一所有者引用多个源时受影响数量只计一次。
- 四张多值关系表和两个系列外键的迁移。
- 目标已存在时不触发复合主键冲突。
- 最终名称等于源名称时可以在同一事务成功。
- 最终名称被第三个词条占用时完整回滚。
- 词条、关联、ordinal 或资料版本在预览后变化时完整回滚。
- 大集合分块过程中间失败时完整回滚。
- 未使用批量删除在任一晚到引用出现时零删除。
- 合并和删除撤销的原子恢复。
- 撤销名称/版本/关联冲突时零恢复。
- 所有外键和同类规范名称唯一约束保持完整。
- 隐私日志允许计数和代码，同时拒绝全部敏感哨兵值。

### 17.3 Desktop

- 三栏布局、类型切换、搜索、筛选、排序和刷新。
- 单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc`。
- 搜索/筛选变化清空选择，排序变化保留选择。
- 0、1、多选右栏状态和命令可用性。
- 已引用阻塞项使整批删除禁用并完整列出。
- 合并对话框的选择内目标、搜索目标和可选最终名称。
- 普通重命名冲突进入预填合并流程。
- 影响总数、待入库/正式库分解和逐项前后差异。
- 提交失败保留选择、输入、预览和滚动位置。
- 成功刷新、目标保持选中、提示条和一次撤销。
- 撤销失效、失败和成功后的正确提示。
- 所有新增控件的稳定 Automation 属性和键盘焦点。

### 17.4 回归与包级测试

- 当前 713 项测试作为最低回归基线，Stage 5C-A 新测试叠加其上。
- Release 构建必须为 0 警告、0 错误。
- Stage 2 至 Stage 5B 的扫描、前置处理、入库、冲突恢复、正式库筛选、批量资料、批量命名和单实例行为保持通过。
- 包级探针使用待入库草稿和正式资产共同验证查询、合并、批量删除、版本更新及撤销。
- 受限 `PATH` 离线启动、原生独立窗口、无浏览器依赖和干净退出继续通过。
- 探针及人工验收后不得残留 TraceFold 或 FFmpeg 进程。

## 18. 人工验收

1. 准备作者、系列、内容标签三类词条，其中包含已引用、未使用和名称相近词条。
2. 分别切换类型，验证名称搜索、全部/已引用/未使用筛选及名称/引用数排序。
3. 验证单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc`，以及 0/1/多选右栏状态。
4. 选择一个未使用词条删除，确认可撤销并恢复相同词条身份。
5. 多选全部未使用词条，预览后原子删除，再执行一次撤销。
6. 混选未使用和已引用词条，确认删除整体禁用并列出全部阻塞项。
7. 选择多个同类源词条，将选择内某项设为目标，确认影响预览和合并结果。
8. 选择一个或多个源词条，通过搜索指定选择外目标，确认结果一致。
9. 分别验证作者、系列和内容标签，不允许跨类型目标。
10. 让同一文件同时包含多个源作者或标签，并让另一文件已经包含目标；确认合并后无重复且顺序符合规则。
11. 使用同时被待入库草稿和正式资产引用的源词条，确认两处资料都迁移且各自只增版一次。
12. 在合并时把目标最终名称改成某个源名称，确认合法；改成第三个词条名称时确认被阻止。
13. 普通重命名为已有名称，确认提示冲突并可直接进入预填合并对话框。
14. 打开预览后修改相关资料或词条，确认旧预览提交时整个操作零修改。
15. 成功合并后执行撤销，确认源词条、目标名称和全部原始关联顺序恢复。
16. 成功合并后再编辑相关资料，确认旧撤销被拒绝且不做部分恢复。
17. 连续完成两次维护操作，确认只能撤销最近一次。
18. 全程检查实际媒体文件名、扩展名、内容和位置均未变化。
19. 解压 Stage 5C-A Windows x64 离线 ZIP，完成受限 `PATH` 启动和上述核心路径。

## 19. 验收标准

1. 词表页以三栏结构清晰区分类型、词条列表和上下文操作。
2. 搜索、筛选、排序和资源管理器式选择行为稳定、可预测。
3. 重复识别完全由用户主导，不存在模糊自动判断或隐式合并。
4. 一个或多个同类源词条可以显式合并到一个现有目标，并可同时确定最终名称。
5. 合并预览准确覆盖待入库草稿和正式资产，逐项结果与最终执行一致。
6. 作者与标签合并去重且保序，系列继续满足零或一个的约束。
7. 每个实际变化的资料所有者只增版一次，陈旧编辑不能覆盖合并结果。
8. 混入已引用词条时批量删除整体失败，不删除引用也不部分成功。
9. 合并、删除和撤销均在单个 SQLite 事务中全有或全无。
10. 最近一次词表维护可在当前会话内安全撤销，任何相关漂移都会阻止完整撤销。
11. 页面错误不清空用户工作，不导致崩溃或半完成状态。
12. 所有操作只修改数据库词条和资料关联，不改变任何物理文件事实。
13. 日志不泄露词条名称、文件名、路径、资料值、哈希或对话框输入。
14. 完整自动化测试、Release 构建、离线包探针和本机人工验收全部通过。

## 20. 交付物与发布边界

- 对应功能提交上的完整自动化测试结果。
- Stage 5C-A Windows x64 离线原生窗口目录和 ZIP。

## 21. 实施顺序约束

1. 先建立管理查询契约，用真实 SQLite 证明引用分解、筛选和稳定排序，再改造页面布局。
2. 先建立词条 Extended Selection 和三种详情状态，再开放批量动作。
3. 先以纯应用测试固定源/目标验证、名称规则和作者/标签/系列迁移算法，再实现预览对话框。
4. 先证明待入库与正式库关联能在同一事务中迁移并完整回滚，再开放合并确认。
5. 先证明混合引用状态会导致批量删除零修改，再开放删除确认。
6. 先证明撤销可以精确恢复且版本只前进，再显示撤销入口。
7. 先接通变化通知和相关撤销失效，再进行跨页面回归。
8. 所有应用和集成测试通过后才扩展包探针并制作离线测试包。
9. 自动包级烟雾通过后再进入人工验收。

本规格没有遗留产品选择。实施中的具体类型和方法名称可以贴合现有代码，但不得削弱显式同类合并、完整影响预览、待入库与正式库同步迁移、原子批量删除、一次性版本化撤销、隐私日志以及不修改物理文件的边界。
