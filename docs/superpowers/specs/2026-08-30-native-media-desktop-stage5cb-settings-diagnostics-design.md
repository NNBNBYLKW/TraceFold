## 1. 目标

Stage 5C-B 将现有只承担目录、自动扫描和前置处理工具简要状态的设置页，扩展为低心智负担的设置与系统诊断工作区。用户无需查找数据库、日志或命令行，即可确认文件管理主链路是否具备安全运行条件，并在发生问题时获得明确影响、稳定错误代码和可执行的人工排查建议。

本阶段建立以下主路径：

```text
进入“设置”
  → 切换到“系统诊断”页签
  → 自动执行一次只读诊断
  → 查看总体状态与五组诊断卡片
  → 对异常项阅读影响和建议步骤
  → 可选：转到文件夹设置 / 打开日志目录 / 复制脱敏摘要
  → 可选：手动重新检查
```

“只读诊断”指不修改业务数据库内容、媒体文件、任务状态、用户设置或持久化诊断历史。为判断目录写权限，探针可以创建一个具有专用随机名称的零内容临时文件，并在同一操作中保证删除；探针不得留下临时文件，也不得读取、移动、重命名或改写用户媒体。

## 2. Stage 5C 边界

Stage 5C 是“管理与质量收口”阶段，按独立纵向切片交付：

1. **Stage 5C-A：词表管理增强**。已完成词表引用查询、显式合并、安全批量删除和会话内撤销。
2. **Stage 5C-B：设置与系统诊断**。本规格覆盖设置页双页签、模块化只读诊断、脱敏摘要和安全排查入口。
3. **后续切片：视觉与发布级 Windows UI Automation 收口**。不属于本规格；本阶段只为新增控件提供稳定可访问名称和 `AutomationId`。

Stage 5C-B 不建立维护任务平台、修复中心、诊断历史或第二套日志系统。诊断只解释当前状态，不能代替现有扫描、恢复、处理和入库状态机做决定。

## 3. 已确认的产品决策

1. 诊断采用模块化编排器，不在 `SettingsViewModel` 中直接访问 SQLite、文件系统或进程 API。
2. 左侧导航继续只有一个“设置”入口；设置页内使用“文件夹与扫描 / 系统诊断”两个页签。
3. 第一次进入“系统诊断”页签时自动检查一次；之后只由用户点击“重新检查”，不持续轮询。
4. 诊断结果只保留在当前软件会话内；不写数据库，不形成历史页。
5. 问题项就地显示影响、建议步骤和安全入口；不为每个问题弹出 Windows 对话框。
6. 诊断不提供修复、清理、重试任务、恢复任务、迁移数据库或修改设置的命令。
7. 后台任务只显示按状态汇总的数量和稳定错误代码，不显示具体文件，也不形成任务中心。
8. 本机界面可以显示完整路径；复制诊断摘要必须自动隐藏用户名、完整路径、文件名、显示名称、词表资料、哈希和媒体内容。
9. 允许的安全入口只有“转到文件夹设置”“打开日志目录”和“复制错误代码”。
10. 一个探针失败、超时或取消不能使整个设置页崩溃，也不能抹掉其他探针的有效结果。
11. 图片和视频使用相同诊断基础设施；本阶段不产生媒体类型专属诊断流程。
12. Stage 5C-B 使用独立离线测试包和包级探针，不覆盖 Stage 5C-A 交付物。

## 4. 范围

### 4.1 包含

- 设置页双页签结构与键盘、焦点和可访问性边界。
- 当前会话内的首次自动检查、手动重新检查、取消和重复运行保护。
- 目录配置、存在性、访问性、写权限、安全包含关系和磁盘空间诊断。
- SQLite 可访问性、应用迁移匹配和 `PRAGMA quick_check` 诊断。
- 随包 FFmpeg 与 FFprobe 的存在性、启动能力和版本识别。
- 排队、运行、中断、失败和恢复等待任务的数量汇总。
- 日志目录、应用数据目录、软件版本、源提交、Windows 与 .NET 运行时信息。
- 总体状态聚合、分类状态、影响、建议步骤和稳定错误代码。
- 本机完整事实与可分享事实的类型化隔离。
- 脱敏纯文本摘要、系统剪贴板复制和已注册日志目录打开。
- 隐私安全结构化日志、自动化测试、包级探针、离线 Windows x64 测试包和人工验收指南。

### 4.2 不包含

- 自动或手动修复、数据库迁移按钮、数据库重建、数据库压缩、数据库备份或恢复。
- 重试、中止、删除、恢复或改变任何后台任务状态。
- 清理工作目录、日志目录、缩略图、临时文件或失败记录。
- 修改三个媒体目录、自动扫描开关、排序偏好、命名预设或其他用户设置。
- 诊断历史表、上次结果持久化、多次结果比较、趋势图或监控通知。
- 具体失败文件、媒体名称、词表值、哈希、完整任务明细或日志内容预览。
- 导出数据库、日志压缩包、媒体清单或完整路径报告。
- 远程遥测、联网检查、在线更新、云端上报或第三方故障分析服务。
- 把诊断页扩展为后台任务中心、恢复中心、文件清理器或高级管理控制台。
- 完整发布级 Windows UI Automation 驱动和整体视觉重做。

## 5. 架构

继续采用 Desktop → Application → Domain / Infrastructure 的依赖方向：

```text
SettingsPage
  ├─ SettingsViewModel                  文件夹、扫描和现有设置
  └─ SystemDiagnosticsViewModel         诊断会话、分组、复制和安全入口
                │
                ▼
        SystemDiagnosticsService
          ├─ ISystemDiagnosticProbe[]   独立探针端口
          ├─ 超时、取消和异常隔离
          ├─ 确定性排序与总体状态
          └─ DiagnosticSummaryFormatter 脱敏摘要
                │
                ▼
Infrastructure probes
  ├─ FolderAndDiskDiagnosticProbe
  ├─ DatabaseDiagnosticProbe
  ├─ ProcessingToolDiagnosticProbe
  ├─ BackgroundWorkDiagnosticProbe
  └─ RuntimeAndLogDiagnosticProbe
```

Domain 层不新增诊断概念。诊断是应用用例与基础设施观察能力，不改变媒体、任务或入库领域模型。

### 5.1 Application 契约

Application 新增只读诊断契约，至少包括：

- `SystemDiagnosticSeverity`：`Healthy`、`Attention`、`Unavailable`。
- `SystemDiagnosticCategory`：`FoldersAndStorage`、`Database`、`ProcessingTools`、`BackgroundWork`、`RuntimeAndLogs`。
- `SystemDiagnosticFactSensitivity`：`Shareable`、`LocalOnly`。
- `SystemDiagnosticFact`：稳定键、显示标签、显示值、敏感级别和确定顺序。
- `SystemDiagnosticItem`：诊断 ID、分类、严重程度、标题、结论、影响、建议、错误代码、事实和安全动作类型。
- `SystemDiagnosticsSnapshot`：运行 ID、开始/完成时间、总体状态、确定排序后的全部项目。
- `ISystemDiagnosticProbe`：探针 ID、失败时默认分类与严重程度、超时和异步检查入口。

探针只返回数据，不返回 WinUI 控件、任意磁盘路径启动命令或可执行委托。异常对象不能进入结果契约。

### 5.2 编排服务

`SystemDiagnosticsService` 负责：

1. 为每次运行创建随机关联 ID 和统一开始时间。
2. 并发启动全部已注册探针。
3. 为目录、工具和运行环境探针使用 5 秒超时；为数据库和后台状态探针使用 15 秒超时；整次运行最多等待 20 秒。
4. 将探针超时转换为探针声明的稳定超时代码；没有专用代码时使用 `diagnostics.probe.timeout`。未分类异常统一转换为 `diagnostics.probe.failed`。
5. 保留成功探针的结果，不因其他探针失败而回滚或清空。
6. 按分类顺序、严重程度、项目顺序和稳定 ID 生成确定结果。
7. 取最严重项目形成总体状态：全部健康为“状态正常”，存在 `Attention` 为“需要注意”，存在 `Unavailable` 为“部分功能不可用”。
8. 尊重页面生命周期取消；用户离开设置页时不发布取消运行的半成品快照。

同一 `SystemDiagnosticsViewModel` 同时只允许一个运行。重复点击“重新检查”不排队、不启动第二个服务调用。

### 5.3 探针注册

探针通过 .NET 依赖注入显式注册。新增内置诊断项只需实现端口并注册，不修改页面运行流程。首版不动态加载外部诊断 DLL，也不允许脚本型诊断。

## 6. 诊断规则

### 6.1 目录与磁盘

目录探针读取已经保存并供当前应用实际使用的目录设置，不诊断尚未保存的文本框草稿。诊断页显示“结果基于已保存设置”；从异常项转到设置页后由用户显式保存，再重新检查。

对待入库目录、正式库目录和工作目录分别检查：

- 是否已配置为有效绝对路径；
- 是否存在且可访问；
- 是否具备写权限；
- 三个规范路径是否相同或互相包含；
- 所在卷总容量和剩余容量。

写权限使用现有安全目录探测语义：在目标目录创建专用随机零内容文件，保持独占句柄并立即删除。取消、失败和异常路径都必须尝试删除；包级探针必须证明没有残留。

相同卷只查询一次容量，但界面仍按三个逻辑目录显示状态。剩余空间小于 10 GiB 或小于卷容量的 10% 时为 `Attention`；磁盘空间本身不触发清理或任务阻止。目录未配置、不存在、不可写或关系不安全为 `Unavailable`。

稳定错误代码至少包括：

- `diagnostics.folder.not_configured`
- `diagnostics.folder.invalid_path`
- `diagnostics.folder.missing`
- `diagnostics.folder.not_writable`
- `diagnostics.folder.unsafe_relationship`
- `diagnostics.storage.space_low`
- `diagnostics.storage.query_failed`

### 6.2 数据库

数据库探针只使用程序自己的 SQLite 数据库和现有连接配置，不接受界面路径。它检查：

- 数据库能否打开并执行只读查询；
- 已应用迁移是否与当前程序迁移集合一致；
- `PRAGMA quick_check` 是否只返回 `ok`。

探针不得调用 `Migrate`、创建表、写诊断记录或修复数据库。数据库无法打开、迁移集合不匹配或 `quick_check` 返回非 `ok` 均为 `Unavailable`。超时单独映射为数据库诊断超时，不能被误报为数据库损坏。

稳定错误代码至少包括：

- `diagnostics.database.unavailable`
- `diagnostics.database.migration_mismatch`
- `diagnostics.database.quick_check_failed`
- `diagnostics.database.timeout`

### 6.3 前置处理工具

工具探针分别检查包内 FFmpeg 和 FFprobe：

- 路径必须来自已注册的包内工具定位器；
- 文件必须存在且不是目录；
- 受控启动 `-version`，捕获有限长度的版本输出；
- 超时后终止本次探测子进程；
- 不读取或处理用户媒体。

两个工具都正常时显示各自版本。任一缺失、无法启动、退出异常或版本无法识别时，前置处理能力为 `Unavailable`，但总体文案必须说明普通图片和不需前置处理的文件仍可管理。

稳定错误代码至少包括：

- `diagnostics.tools.ffmpeg_missing`
- `diagnostics.tools.ffprobe_missing`
- `diagnostics.tools.launch_failed`
- `diagnostics.tools.version_unknown`
- `diagnostics.tools.timeout`

### 6.4 后台状态

后台状态探针通过 Application 定义的只读汇总端口读取：

- 排队处理任务数量；
- 正在运行任务数量；
- 中断任务数量；
- 失败任务数量；
- 等待恢复或清理的入库操作数量。

排队和正常运行数量属于健康事实。中断、失败或恢复等待数量大于零时为 `Attention`。读取失败时显示 `diagnostics.background.query_failed`，但不列出任务 ID、文件名、路径或错误原文，也不提供重试按钮。

### 6.5 日志与运行环境

运行环境探针检查并显示：

- 产品版本与程序集信息版本；
- 包清单中的 Stage 检查点和 Git 源提交；
- Windows 版本和 .NET 运行时版本；
- 应用数据目录与日志目录；
- 日志目录是否存在、可访问和可写。

不存在包清单时显示 `Attention` 和 `diagnostics.runtime.manifest_missing`；存在清单但格式无效或与程序集版本矛盾时为 `Unavailable`。发布脚本和包级烟雾仍在应用启动前独立阻止缺少清单的正式离线包。日志目录不可写为 `Attention`，因为媒体管理仍可能运行，但故障证据可能无法保存。

日志写权限使用与目录探针相同的零内容临时文件策略，不写虚假业务日志。

## 7. Desktop 界面与交互

### 7.1 设置页结构

`SettingsPage` 顶部使用原生页签控件，包含：

1. **文件夹与扫描**：保留现有目录选择、自动扫描、上次扫描、工具简要状态和保存设置。
2. **系统诊断**：新增诊断头部、状态卡片和安全排查入口。

左侧 Shell 导航不新增项目。默认继续进入“文件夹与扫描”，避免现有设置入口行为突变。

### 7.2 诊断头部

诊断头部显示总体状态、最近检查时间、“重新检查”和“复制诊断摘要”。首次运行前显示“尚未检查”。第一次进入诊断页签自动运行。

首次运行期间显示进度状态且没有旧卡片。重新检查期间保留上一份完整结果，头部显示“正在重新检查”；复制按钮在运行完成前禁用，避免复制旧结果并误认为新结果。

成功、提醒和不可用使用 WinUI 主题资源、图标和文字共同表达，不能只依靠颜色。

### 7.3 分组与项目

结果按以下顺序分组：

1. 目录与磁盘
2. 数据库
3. 前置处理工具
4. 后台状态
5. 日志与运行环境

总体状态位于头部，不重复作为第六张内容卡片。每组内先显示 `Unavailable`，再显示 `Attention`，最后显示 `Healthy`。健康项保持紧凑；提醒和不可用项自动展示影响、建议步骤和错误代码。

### 7.4 安全动作

诊断结果只能声明以下动作枚举：

- `NavigateToFolderSettings`
- `OpenRegisteredLogFolder`
- `CopyErrorCode`

Desktop 将动作枚举映射为具体 UI 行为。打开日志目录必须从应用的 `IAppDataPathProvider` 读取已注册日志根目录，不能使用结果文本或用户输入路径。路径不存在时禁用动作并显示稳定提示。

“转到文件夹设置”切换页签并将键盘焦点移动到对应目录行。所有动作完成或失败后焦点返回触发按钮或明确的目标控件，不打开连续弹窗。

## 8. 脱敏摘要

`DiagnosticSummaryFormatter` 是 Application 层纯函数。它只接受完整快照并只输出 `Shareable` 事实；任何 `LocalOnly` 事实即使显示标签安全，也不能进入复制文本。

摘要采用确定性纯文本，至少包含：

- 诊断关联 ID 和本地检查时间；
- 软件版本、Stage 检查点和源提交；
- Windows 与 .NET 版本；
- 总体状态；
- 各分类与各项状态；
- 任务状态数量；
- 磁盘总量和剩余量；
- FFmpeg / FFprobe 版本；
- 稳定错误代码。

摘要不得包含：

- 用户名或计算机名；
- 完整路径、盘符后的目录结构或 UNC 主机名；
- 数据库文件名、日志文件名或媒体文件名；
- 显示名称、作者、系列、标签或命名规则文本；
- 媒体哈希、探针临时文件名或异常堆栈；
- 任务 ID、资产 ID、词条 ID 或数据库记录内容。

目录在摘要中只使用“待入库目录”“正式文件库目录”“工作目录”“应用数据目录”“日志目录”等逻辑名称。复制失败只显示 `diagnostics.clipboard.copy_failed`，不记录剪贴板内容。

## 9. 生命周期、并发与失败恢复

`SystemDiagnosticsViewModel` 维护一个页面生命周期取消源和一个运行门：

- 第一次选择诊断页签时只触发一次自动运行；
- 同一时刻只允许一次运行；
- 重新检查不排队；
- 页面卸载时取消当前运行；
- 取消不替换上一份完整快照；
- 页面仍在当前软件会话内时保留最近完整快照；
- 软件关闭后结果自然丢失。

探针必须遵守取消令牌。工具探针取消或超时时必须结束自己启动的子进程；目录与日志探针必须删除自己创建的临时文件；数据库和后台探针不得留下打开的上下文、事务或数据读取器。

诊断服务不捕获或处理现有后台工作器的生命周期，也不等待任务进入静止状态。结果是检查完成时的观察快照，不是并发控制凭证。

## 10. 错误处理与日志

每项结果都必须使用稳定错误代码和面向用户的固定文案。内部异常只进入结构化日志，不进入界面或复制摘要。

诊断日志只允许记录：

- 诊断关联 ID；
- 探针稳定 ID；
- 开始、完成、超时或取消阶段；
- 持续时间；
- 结果数量和严重程度；
- 稳定错误代码。

日志不得记录完整路径、文件名、目录名、工具输出原文、数据库内容、任务 ID、媒体资料、哈希、摘要文本或异常消息中的用户数据。异常对象可以由日志框架记录类型和内部堆栈，但调用方不得把用户事实插入消息模板或作用域字段；隐私测试使用哨兵值证明日志中不存在这些内容。

## 11. 可访问性与 UI Automation 边界

新增控件必须提供稳定 `AutomationId` 和中文可访问名称，至少包括：

- 设置页签容器及两个页签；
- 诊断总体状态；
- 最近检查时间；
- 重新检查；
- 复制诊断摘要；
- 每个诊断分组；
- 错误代码文本与复制按钮；
- 转到文件夹设置；
- 打开日志目录。

键盘用户可以通过 Tab 到达所有动作，Enter / Space 执行，页签切换后焦点进入新页签标题或主要内容。屏幕阅读器必须同时听到状态文字和项目标题，不能只读图标。

完整发布级 Windows UI Automation 驱动仍留给后续 Stage 5C 切片；本阶段通过 ViewModel、结构测试、可访问边界和人工键盘验收保护新增界面。

## 12. 测试策略

### 12.1 Application 单元测试

- 健康、提醒和不可用总体状态聚合。
- 多探针确定排序和单项失败隔离。
- 默认与数据库探针超时映射。
- 页面取消时不返回半成品快照。
- 摘要只包含 `Shareable` 事实。
- 用户名、完整路径、文件名、资料、哈希、ID、异常文本和本地事实哨兵不出现在摘要或日志。
- 相同输入生成完全相同的纯文本摘要。

### 12.2 Infrastructure 测试

- 三个隔离临时目录的存在、写权限、安全关系和空间结果。
- 不可写、缺失、包含关系和容量查询失败。
- 临时写探针在成功、失败和取消后零残留。
- SQLite 可访问、迁移匹配、`quick_check` 成功、失败和超时。
- 工具缺失、版本成功、异常退出、无效输出、超时和子进程清理。
- 后台状态各类数量汇总且不读取或返回文件事实。
- 正式包清单、开发环境清单缺失、版本字段无效。
- 日志目录存在、不可写和临时文件零残留。

### 12.3 Desktop 测试

- 首次选择诊断页签只自动运行一次。
- 重复刷新不产生并行调用。
- 刷新保留旧结果，完成后原子替换。
- 取消和失败后状态、按钮和提示一致。
- 脱敏摘要复制成功和剪贴板失败。
- 安全动作枚举到已注册页面、焦点和目录启动器的映射。
- 所有新增控件的 `AutomationId`、可访问名称、键盘焦点和非纯颜色状态表达。
- 原 `SettingsViewModel` 的文件夹、自动扫描和工具简要状态行为保持通过。

### 12.4 回归与隐私

- 当前 810 项测试为最低回归基线，Stage 5C-B 新测试叠加其上。
- Stage 1 至 Stage 5C-A 的扫描、处理、入库、冲突恢复、批量编辑、命名、词表维护、单实例和离线启动保持通过。
- 架构测试禁止 Desktop 直接引用 EF Core、SQLite、文件系统或进程 API。
- 诊断不改变数据库业务表、目录设置、任务状态、媒体文件或包内工具。

Stage 5C-B 新增独立检查点：

- 发布参数：`StageCheckpoint 5C-B`
- 产品信息版本：`4.0.0-stage5cb+<source-commit>`
- 目录：`dist/TraceFold-MediaDesktop-Stage5C-B-win-x64`
- ZIP：`dist/TraceFold-MediaDesktop-Stage5C-B-win-x64.zip`
- 包级场景：`stage5cb-diagnostics`
- 包级结果：`stage5cb-diagnostics-probe-result.json`

Stage 5C-B 探针使用自己拥有的临时根目录和数据库，通过公开应用服务验证：

- 健康目录、磁盘、数据库、工具、后台状态和运行环境结果；
- 一个受控故障不会丢失其他探针结果；
- 总体严重程度和稳定错误代码；
- 摘要脱敏；
- 数据库业务数据、设置、任务状态和媒体夹具零变化；

## 14. 人工验收重点

人工指南至少覆盖：

1. 设置页仍默认显示现有文件夹与扫描功能。
2. 页签键盘切换、焦点和屏幕阅读器名称。
3. 第一次进入诊断页自动运行且只运行一次。
4. 总体状态、时间、分类顺序和正常项紧凑展示。
5. 重新检查期间旧结果保留且重复点击无并行运行。
6. 三个已保存目录、空间和完整本机路径显示正确。
7. 未保存目录草稿不被当作当前活动配置。
8. FFmpeg 与 FFprobe 分别显示版本。
9. 数据库、迁移和 `quick_check` 正常。
10. 后台状态只有数量，无具体文件。
11. 人为制造缺失目录或不可用工具副本后显示“部分功能不可用”，其他卡片仍正常。
12. 问题项显示影响、建议步骤和错误代码，不连续弹窗。
13. “转到文件夹设置”切换页签并返回正确焦点。
14. “打开日志目录”只打开程序日志根目录。
15. 复制摘要不含用户名、路径、文件名、资料、哈希或 ID。
16. 诊断前后数据库业务事实和媒体目录树比较无差异。
17. 诊断后无临时探针文件、FFmpeg/FFprobe 或 TraceFold 残留进程。
18. 解压 Stage 5C-B 离线包，在受限 `PATH` 下完成核心路径。

## 15. 完成标准

Stage 5C-B 只有同时满足以下条件才可进入人工验收：

1. 设置页双页签不增加左侧导航负担。
2. 诊断编排、探针实现和 Desktop 展示保持既有分层边界。
3. 六类用户可见信息完整：目录与磁盘、数据库、工具、后台状态、日志与运行环境、总体结论。
4. 首次自动运行、手动刷新、取消和重复运行保护行为一致。
5. 一个探针失败或超时不会使整页失败。
6. 诊断不修改业务数据、设置、任务状态或媒体文件，临时写探针零残留。
7. 后台任务只显示数量，不演化为任务中心。
8. 摘要和日志通过隐私哨兵测试。
9. 所有新增控件具备稳定可访问名称、`AutomationId` 和键盘焦点路径。
10. 全量测试在 810 项基线上继续增长并全部通过。
11. Stage 5C-B 独立离线包级探针通过，不覆盖 Stage 5C-A 包。
12. 人工指南、ZIP 哈希、版本和源提交证据齐全；人工结果在用户实际报告前保持待验证。

## 16. 实施顺序约束

后续实施计划必须遵循以下顺序：

1. 先以测试驱动定义诊断契约、聚合和脱敏摘要。
2. 再逐个实现基础设施探针及失败隔离，不先写大型设置界面。
3. 先证明探针不修改业务事实、临时文件零残留和工具子进程可清理，再接入 Desktop。
4. 将诊断状态拆入独立 `SystemDiagnosticsViewModel`，不继续扩大 `SettingsViewModel` 责任。
5. 完成双页签和安全动作后补齐焦点、可访问性和结构测试。
6. 最后增加 Stage 5C-B 包级探针、离线发布脚本和人工验收指南。
7. 每个纵向任务都以红—绿—重构执行，并形成可独立审查的提交。

本规格没有遗留产品选择。实施中的类型和文件命名可以贴合现有代码，但不得削弱只读边界、单项失败隔离、当前会话结果、任务汇总粒度、脱敏摘要、已注册安全入口或独立 Stage 5C-B 包的约束。
