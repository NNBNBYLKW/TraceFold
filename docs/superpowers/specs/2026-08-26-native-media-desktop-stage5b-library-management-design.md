## 1. 目标

Stage 5B 解决正式文件库在资产增多后难以快速定位、批量整理和统一显示名称的问题。它保留 TraceFold 的核心边界：软件管理资料和显示名称，磁盘中的实际文件名、扩展名、内容和位置不因本阶段操作而改变。

本阶段建立以下主路径：

```text
搜索 / 组合筛选 / 排序
  → 资源管理器式多选
  → 在一个对话框中编辑资料和命名规则
  → 实时预览全部结果
  → 原子提交全部资料与显示名称
  → 可选：撤销最近一次批量修改
```

批量命名参考 OneCommander File Automator 的“预设 + 有序规则 + 结果预览”思路，但界面、概念和数据边界遵循 TraceFold 现有 WinUI 桌面端，不复制其品牌或把文件处理能力带入正式库。

## 2. Stage 5 边界

Stage 5 已拆成三个可独立验收的纵向切片：

1. **Stage 5A：批量待入库效率**。已完成资源管理器式多选、批量资料、批量前置处理排队和批量入库编排。
2. **Stage 5B：正式库管理效率**。本规格覆盖组合筛选、排序、正式资产多选、批量资料编辑和规则化批量显示名称。
3. **Stage 5C：管理与质量收口**。后续处理词表管理增强、设置诊断、完整 Windows UI Automation 和整体视觉收尾。

Stage 5B 复用 Stage 5A 已形成的选择快照、资料变更语义和原子事务经验，但不让正式资产伪装成待入库项目，也不抽象出包含状态分支的万能批量平台。

## 3. 已确认的产品决策

1. 所有搜索和筛选条件之间使用严格交集语义。
2. 同时选择多个作者或多个内容标签时，资产必须包含所选类别中的全部词项。
3. 筛选覆盖媒体类型、作者、系列、内容标签、作者/系列/标签缺失，以及显示名称是否已自定义。
4. 筛选按钮打开紧凑浮出面板；生效条件以可逐项移除的标签持续显示。
5. 正式库支持按入库时间、显示名称、实际文件名和媒体类型排序，并支持升序和降序。
6. 软件重启后只恢复排序；搜索文本和筛选条件在新会话中清空。
7. 搜索或筛选变化会清空当前选择并给出提示；排序变化保留选择。
8. 正式资产采用与 Windows 资源管理器一致的单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc` 选择方式。
9. 批量资料和批量命名合并为一个大型原生对话框，使用“资料”和“命名”两个页签。
10. 两个页签的变更通过一次应用动作在同一个 SQLite 事务中提交；任何错误都会阻止并回滚整个批次。
11. 批量命名只修改数据库中的显示名称，不修改物理文件名、扩展名、文件内容或文件位置。
12. 每个命名预设选择“实际文件名”或“当前显示名称”为来源，默认使用实际文件名。
13. 首版规则包含前缀/后缀、普通查找替换、删除指定文本或括号内容、大小写转换、连续编号和资料占位符。
14. 首版不支持正则表达式、条件分支、自动运行预设或文件处理操作。
15. 多作者和多标签按资料中的稳定顺序连接；分隔符可配置，默认为 `、`。
16. 连续编号按打开批量对话框时的正式库显示顺序生成。
17. 空结果、超长结果、缺少占位符资料或无效规则会阻止整个批次。
18. 重复显示名称允许提交，但预览必须警告。
19. 命名预设保存在本地数据库，供正式库手动调用；不在扫描、入库或启动时自动执行。
20. 成功提交后只提供一次会话内撤销；下一次相关编辑、版本冲突或软件关闭会使其失效。

## 4. 范围

### 4.1 包含

- 正式库数据库侧组合查询和明确的排序契约。
- 筛选浮出面板、有效条件标签和清空条件。
- 正式资产 Extended Selection、选择汇总和批量操作入口。
- 正式资产的批量作者、系列和内容标签编辑。
- 大型“批量编辑”原生对话框及“资料 / 命名”页签。
- 可增删、启停和调整顺序的命名规则链。
- 命名来源、实时逐项预览、问题定位和重复名称警告。
- 命名预设的新建、另存、覆盖、加载和删除。
- 资料与显示名称的原子批量提交。
- 最近一次相关批量修改的会话内撤销。
- 新控件的稳定 `AutomationId`、可访问名称和键盘焦点规则。
- 自动化测试、包级探针、离线 Windows x64 测试包和人工验收清单。

### 4.2 不包含

- 修改磁盘中的实际文件名、扩展名、目录或媒体内容。
- 正则表达式、脚本、条件规则或用户自定义代码。
- 自动触发命名预设、监控文件后自动改名或入库时自动命名。
- 持久化撤销栈、批量历史页面或批量任务状态机。
- 文件删除、格式转换、音视频处理或前置处理器扩展。
- 正式库分页、虚拟文件夹或保存筛选方案。
- 词表管理增强、设置诊断和完整 Windows UI Automation 驱动。

## 5. 架构

采用“Desktop 会话状态 + Application 纯规则与编排 + Infrastructure 原子查询和持久化”：

```text
LibraryPage / LibraryViewModel
  ├─ 搜索、筛选、排序和选择状态
  ├─ 筛选浮出面板
  └─ 批量编辑对话框
          │
          │  选择快照、资料草稿、预设和规则
          ▼
Application
  ├─ LibraryQueryService
  ├─ LibraryBatchEditorService
  ├─ NamingRuleEngine（纯函数）
  └─ NamingPresetService
          │
          ▼
Infrastructure
  ├─ EF / SQLite 组合查询
  ├─ 正式资产批量编辑事务
  ├─ 命名预设持久化
  └─ 事务提交后的变化通知
```

依赖方向保持：

```text
Desktop → Application → Domain
Desktop → Infrastructure → Application / Domain
```

`NamingRuleEngine` 不依赖 WinUI、EF、文件系统或系统区域设置。它接收不可变输入和规则，返回结果、警告和错误。预览和正式执行必须调用同一规则引擎。

`LibraryBatchEditorService` 是本阶段唯一的批量提交编排边界。它组合资料变更与命名结果，但不承担筛选 UI、规则控件状态或文件操作。Stage 5A 的纯资料集合变更逻辑可以复用；绑定待入库状态的 `IBatchMetadataStore`、`InboxSelectionEntry` 和操作权限判断不能直接用于正式资产。

本阶段不新增 `Batch` 领域聚合、批量任务表或批量历史表。

## 6. 正式库查询、筛选与排序

### 6.1 查询条件

正式库查询契约使用一个不可变条件对象，包含：

- 搜索文本；
- 单值媒体类型：全部、图片或视频；
- 多个作者 ID；
- 零或一个系列 ID；
- 多个标签 ID；
- 作者、系列、标签各自的“缺失”条件；
- 显示名称状态：全部、已自定义或仍使用实际文件名；
- 排序字段和方向。

搜索文本继续匹配实际文件名或显示名称。搜索、所有筛选类别及缺失条件之间使用 `AND`。多个作者和多个标签分别使用“全部包含”，不能使用“命中任意一个”。

媒体类型和显示名称状态是单选条件。一个资产最多属于一个系列，所以系列筛选也是单选；“缺少系列”和具体系列互斥。选择具体作者时不能同时选择“缺少作者”，选择具体标签时不能同时选择“缺少标签”，界面必须阻止这些必然无结果的组合。

“仍使用实际文件名”按数据库中 `DisplayName` 是否为空判断；即使用户显式把显示名称设成与实际文件名相同，它仍属于“已自定义”。

### 6.2 查询执行

Infrastructure 在 SQLite 中完成筛选，不先加载全部正式资产再在 Desktop 内存过滤：

- 作者和标签使用关联表上的 `EXISTS`、计数或等价查询，确保满足全部所选 ID；
- 缺失条件使用 `NOT EXISTS` 或空系列外键；
- 搜索对 `%`、`_` 和转义字符保持现有安全转义；
- 排序使用稳定次级键，最终以资产 ID 保证确定顺序。

入库时间默认降序；其他文本排序使用与现有界面一致的不区分大小写比较。连续编号使用查询返回的确定顺序，而不是 GridView 当前可见卡片的顺序。

### 6.3 筛选交互

正式库顶部保留搜索框，并增加：

- 排序字段；
- 升序 / 降序切换；
- 显示有效条件数量的“筛选”按钮；
- 筛选按钮下方可逐项移除的有效条件标签；
- 有筛选时的“全部清除”。

点击“筛选”打开紧凑浮出面板。面板中的修改是草稿，点击“应用”后一次性替换当前筛选并收起；点击“取消”不改变查询。这样不会因连续勾选多个条件反复刷新列表或反复清空选择。

搜索文本发生实际变化或应用了不同筛选时，清空已有选择并显示“查询条件已变化，已取消选择”的非阻塞提示。移除条件标签和“全部清除”遵循同一规则。只改变排序时保留按资产 ID 记录的选择，并根据新顺序重建选择锚点和编号顺序。

排序设置写入现有本地设置边界；搜索和筛选只保存在当前进程会话中。

## 7. 正式资产选择与页面状态

正式库卡片区改为 Extended Selection：

- 普通单击只选择当前资产；
- `Ctrl` 单击添加或移除资产；
- `Shift` 从焦点锚点连续选择；
- `Ctrl+A` 选择当前查询结果中的全部资产，包括滚动区外的匹配项；
- `Esc` 清空选择。

选择顺序不是点击先后，而是当前查询排序顺序。普通刷新按资产 ID 对选择做交集，只移除已不存在或不再匹配当前查询的项目。

右侧区域按选择数量切换：

- 0 项：保持空状态；
- 1 项：保持现有预览、技术摘要、资料编辑和“打开所在目录”；
- 2 项及以上：显示选择总数、图片/视频数量、资料覆盖摘要和批量编辑入口，不显示会让用户误认为只修改一个资产的单项输入控件。

多选后中间区顶部显示轻量批量操作栏：“已选择 N 项”“批量编辑”“取消选择”。本阶段没有批量打开目录、删除或文件处理按钮。

## 8. 统一批量编辑对话框

批量编辑使用已确认的大型原生对话框。顶部明确显示选择数量和“仅修改软件资料，不修改实际文件”。对话框分为两个页签：

1. **资料**：复用 Stage 5A 的追加、移除和替换语义。作者和标签支持追加、移除、替换与明确清空；系列只支持替换或明确清空；每个替换字段默认“不修改”。
2. **命名**：左侧为预设和名称来源，中部为有序规则链与当前规则参数，右侧为“实际文件名 / 当前显示名称 / 新显示名称”逐项实时预览。

两个页签共享同一个不可变选择快照和一个提交动作。只修改资料、只修改命名或同时修改均可，但至少要有一项实际变化。对话框草稿变化只在内存中计算，不写数据库。

资料页中的拟议修改先应用到内存快照，命名页再使用“修改后的资料”解析占位符。例如同一批次新增作者并使用作者占位符时，预览和最终名称必须包含新增作者。

预览始终跟随当前草稿更新。底部的应用按钮触发最终重新验证和原子提交，不建立第二个批量向导。出现错误时保留两个页签的全部输入和滚动位置，并定位到预览中的第一个错误项目。

## 9. 命名来源、规则和预览

### 9.1 名称来源

- **实际文件名**：取实际文件名最后一个扩展名之前的基本名称。例如 `IMG_0001.webp` 的输入为 `IMG_0001`。物理扩展名不参与生成，也不会被修改。
- **当前显示名称**：存在显式显示名称时按存储值使用；没有显式显示名称时回退到不含扩展名的实际文件名。

来源在一个预设内固定，默认选择实际文件名。规则从来源字符串开始，严格按用户排列顺序执行；禁用规则跳过但保留配置。

### 9.2 首版规则

1. **添加前缀 / 后缀**：在当前名称前后添加普通文本。
2. **普通查找替换**：替换字面文本，可选择是否区分大小写；不解释正则表达式。
3. **删除内容**：删除指定的字面文本，或删除选定成对括号及其内部内容。括号处理按所选括号对从左到右执行；未配对括号保持原样，不猜测跨段范围。
4. **大小写转换**：使用不受系统区域设置影响的规则转换英文字母为大写或小写；中文、数字和符号不变化。
5. **连续编号**：配置起始值、步长、最小位数，以及添加在名称之前或之后。编号依据选择快照中的排序序号。
6. **资料占位符**：通过文本模板插入或组成名称，支持来源名称、作者、系列、内容标签和连续编号。模板可以不包含来源名称，因此能够生成“系列 - 作者 - 001”这类纯资料名称。

规则文本参数均作为普通文本保存。首版没有转义语言、表达式求值、嵌套函数或条件执行。

作者和标签按照正式资产关联表中的稳定 ordinal 顺序输出，默认用 `、` 连接；规则可为该字段选择其他普通文本分隔符。系列为零或一个。占位符引用的资料缺失时，该资产产生阻断错误，不静默输出空文本。

### 9.3 结果校验

预览和提交使用相同的纯规则引擎，并执行以下校验：

- 最终结果去除首尾空白后不能为空；
- 最终结果不能超过现有 `MediaAsset.DisplayName` 的 1024 字符限制；
- 占位符所需资料必须存在；
- 规则类型、参数、顺序、序号范围和预设版本必须有效；
- 所有选中资产都必须成功计算。

无变化项目显示“无变化”，提交时不增加资料版本。生成结果在当前批次内重复，或与未选择正式资产的显示名称重复时显示警告，但不阻止提交；显示名称没有唯一性约束，重复不会被当作文件冲突。

任一阻断错误都会禁用应用。预览按资产显示稳定错误代码对应的用户提示，并同时在规则列表标记造成问题的规则。

## 10. 命名预设

命名预设是正式库全局可用的本地配置，至少包含：

- 稳定预设 ID；
- 名称来源；
- 有序规则列表及启用状态；
- 每条规则的类型和参数；
- 配置架构版本；
- 创建和更新时间。

规则配置使用带显式类型标识和版本号的序列化结构保存到 SQLite。未知规则类型、缺失必填参数或高于当前程序支持版本的预设可以显示，但必须标记为不可执行，不能忽略未知部分后运行。

预设名称去除首尾空白后不能为空，并在不区分大小写的比较下保持唯一。“另存为”遇到同名预设时要求明确覆盖；删除预设只删除配置，不改变任何资产。编辑预设草稿不会自动覆盖，只有用户选择“保存”或“覆盖”才写入数据库。

预设只由用户在正式库中手动加载和执行。扫描、前置处理、正式入库、软件启动和自动刷新均不得调用预设。

## 11. 应用层契约和数据流

### 11.1 选择快照

批量编辑使用独立的正式资产选择条目，至少包含：

- 资产 ID；
- 期望资料版本；
- 当前查询顺序 ordinal。

Desktop 不向应用层传递磁盘路径、SHA-256 或用于修改物理文件的命令。

### 11.2 打开和预览

打开对话框时，应用层按选择快照加载不可变资产资料，包括实际文件名、显式显示名称、作者、系列、标签和资料版本。加载数量不完整或版本已经变化时拒绝打开，并要求刷新选择。

Desktop 持有资料编辑草稿、命名预设草稿和预览结果。每次草稿变化执行以下纯内存顺序：

1. 根据追加、移除、替换和清空语义计算每项的拟议资料；
2. 以拟议资料和选定名称来源建立命名输入；
3. 按选择 ordinal 执行规则链；
4. 汇总无变化、警告和阻断错误。

### 11.3 原子应用

应用命令包含选择快照、资料编辑意图和不可变命名规则快照。Infrastructure 在一个 SQLite 事务中：

1. 重新加载全部正式资产及资料关联；
2. 比较每项资料版本；
3. 解析或创建合法的作者、系列和标签词项；
4. 再次计算拟议资料；
5. 使用同一规则引擎重新生成并校验全部显示名称；
6. 写入发生变化的资料关联、系列和显示名称；
7. 为发生变化的资产各增加一次资料版本；
8. 构建撤销回执并提交事务；
9. 事务提交后发布一次合并变化通知。

任何资产缺失、版本变化、词项失效、规则失效、名称非法或数据库写入失败都会回滚整个事务。Desktop 的实时预览不是安全凭证，不能替代提交时的重新计算。

为避免 SQLite 参数限制，大选择可以分块读取和写入，但所有分块必须共享同一事务。批量操作不写物理文件，因此不需要跨数据库和文件系统的恢复状态机。

## 12. 一次性撤销

成功提交返回会话内撤销回执。回执只保存在当前进程内存中，包含受影响资产的修改前资料、修改后资料版本以及恢复所需的稳定标识，不包含文件内容或持久化批量历史。

成功提示条提供“撤销本次批量修改”。执行撤销时在一个 SQLite 事务中重新验证全部资产仍处于回执记录的修改后版本，然后恢复显示名称、作者、系列和标签；任何一项版本不一致都会拒绝整个撤销，不进行部分恢复。

以下事件使回执失效并关闭撤销入口：

- 回执涉及的任一资产又发生单项或批量资料编辑；
- 用户完成下一次相关批量编辑；
- 撤销检测到版本冲突；
- 软件关闭。

撤销恢复资产关联和显示名称，但不会自动删除批量操作期间新建的词表项。词表项可能已被其他资产引用，自动删除会扩大撤销范围；未引用词项留给既有或 Stage 5C 词表管理处理。

## 13. 并发、刷新和命令门

同一窗口同一时间只允许一个正式库批量提交或撤销命令。对话框提交期间禁用重复提交，但数据库版本比较仍是最终并发保护，不能只依赖按钮状态。

批量对话框打开后，列表排序或后台通知不能改变已捕获的 ordinal。外部资料更新可以继续到达；应用时由版本检查拒绝陈旧快照。失败后不自动用新资料重放旧命令。

提交成功后正式库执行一次合并刷新：

- 保留仍匹配当前查询的资产选择；
- 若修改使资产不再满足筛选，则从当前列表和选择中移除；
- 重新加载单选详情或多选汇总；
- 按当前排序重排卡片；
- 显示成功数量、无变化数量、警告数量和撤销入口。

搜索和筛选重载使用现有或等价的取消/串行门，避免较慢的旧查询覆盖较新的条件。缩略图解析失败只影响对应预览，不得使组合查询或批量资料失效。

## 14. 错误处理与隐私

应用层至少区分以下稳定错误类别：

- 选择为空、重复或已经失效；
- 正式资产缺失；
- 资料版本冲突；
- 词项无效、缺失或名称冲突；
- 命名预设版本或规则无效；
- 名称为空、超长或缺少占位符资料；
- 持久化失败；
- 撤销不存在、已失效或版本冲突。

用户提示使用安全显示名称或列表行定位问题；日志只记录批量操作 ID、资产数量、规则类型、阶段、耗时、结果计数和稳定错误代码。日志不得记录完整路径、实际文件名、显示名称、预设文本参数、作者、系列、标签、哈希或生成后的名称。

重复名称属于警告，不映射为错误代码。用户可以在预览中确认后正常提交，无需执行文件冲突决策。

## 15. 可访问性与自动化准备

本阶段新增或改变的控件必须有稳定 `AutomationId` 和可访问名称，包括：

- 正式库搜索、排序字段、方向和筛选按钮；
- 筛选浮出面板、各筛选类别、应用、取消、条件标签和全部清除；
- 正式库 Extended Selection 列表、批量工具栏、批量编辑和取消选择；
- 批量对话框、资料/命名页签、预设列表、名称来源和规则列表；
- 添加、删除、启用、禁用、上移和下移规则；
- 规则参数、预览表、错误定位、保存预设、应用和取消；
- 成功提示条及撤销按钮。

键盘焦点规则：

- 打开筛选面板后进入第一个筛选控件，关闭后返回筛选按钮；
- 打开批量对话框后进入当前页签第一个可编辑控件；
- 切换页签不丢失另一个页签的草稿；
- 预览出现错误时应用命令把焦点移动到第一个错误行或对应规则；
- 关闭对话框后返回正式库选择；
- 撤销完成后返回正式库列表，不抢夺用户正在操作的搜索框焦点。

Stage 5B 提供稳定自动化边界，但完整发布程序 UI Automation 驱动仍属于 Stage 5C。

### 16.1 Domain 和 Application

- 查询条件规范化和必然矛盾条件的拒绝。
- 多作者、多标签及跨类别严格交集语义。
- 四种排序字段、两个方向和稳定次级顺序。
- 正式库选择快照的 ID、版本和 ordinal 校验。

- 拟议资料先于命名占位符解析。
- 每种命名规则的正常、边界和非法参数。
- 多规则顺序、禁用规则和预览/执行一致性。
- 实际文件名去扩展名和显示名称来源回退。
- 多作者、多标签稳定顺序和自定义分隔符。
- 编号起始值、步长、最小位数和当前排序顺序。

- 任一项目失败时整个批次失败。
- 一次性撤销、失效、版本冲突和第二次撤销拒绝。

### 16.2 Infrastructure 集成

使用真实 SQLite 覆盖：

- 搜索与媒体类型、作者、系列、标签、缺失资料和显示名称状态组合。
- 多作者和多标签必须全部匹配，而不是任意匹配。
- `DisplayName IS NULL` 与内容相同但显式自定义的区别。
- 至少 600 个正式资产上的筛选、稳定排序和选择顺序。
- 资料与显示名称在一个事务中提交。
- 分块处理中间失败时完整回滚。
- 事务内新建或复用词项后，命名占位符使用最终资料。
- 版本变化、词项变化或非法生成结果导致完整回滚。
- 命名预设创建、覆盖、加载、删除和版本不兼容处理。
- 撤销原子恢复及版本冲突时零修改。
- 日志不包含路径、文件名、资料、规则参数、哈希或生成名称。

### 16.3 Desktop

- 筛选按钮、浮出面板、应用/取消和有效条件标签。

- 单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc`。
- `Ctrl+A` 只选择当前查询结果。

- 统一对话框两个页签共享草稿和一次提交。
- 预设列表、来源选择、规则增删启停和顺序调整。
- 实时预览、无变化、警告、错误定位和应用门。
- 失败保留输入，成功刷新并显示撤销入口。
- 所有新增控件的稳定 Automation 属性和键盘焦点。

### 16.4 回归与包级测试

## 17. 人工验收

1. 准备包含图片、视频、多作者、多标签、不同系列和资料缺失项的正式库。
2. 分别组合媒体类型、作者、系列、标签、缺失资料和显示名称状态，确认只显示满足全部条件的资产。
3. 选择两个作者或两个标签，确认只显示同时包含全部所选词项的资产。
4. 应用、取消、逐项移除和全部清除筛选，确认条件标签及数量正确。
5. 多选后改变搜索或筛选，确认选择被清空并提示；只改变排序时选择保留。
6. 验证单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc`，以及多选详情摘要。
7. 在一个批量对话框中同时修改作者/系列/标签和显示名称，确认命名占位符使用修改后的资料。
8. 逐一验证前后缀、普通替换、删除文本/括号内容、大小写、编号和资料占位符。
9. 切换实际文件名和当前显示名称来源，确认扩展名不参与实际文件名来源。
10. 调整规则顺序和启用状态，确认实时预览与最终结果一致。
11. 保存、覆盖、加载和删除预设，重启后确认预设仍存在且不会自动运行。
12. 制造空名称、超长名称和缺少占位符资料，确认整个批次无法提交且输入保留。
13. 制造重复显示名称，确认只警告并允许提交。
14. 提交前单独修改一个选中资产，确认版本冲突使整个批次零修改。
15. 成功后执行一次撤销，确认资料和显示名称全部恢复；再次编辑相关资产后确认旧撤销失效。
16. 检查磁盘上的实际文件名、扩展名、内容和位置始终未变化。
17. 解压 Stage 5B Windows x64 离线 ZIP，完成受限 `PATH` 本机烟雾和上述核心路径。

## 18. 验收标准

1. 正式库能通过严格交集组合筛选稳定定位资产。
2. 搜索、筛选、排序和选择的相互影响清晰且可预测。
3. 正式库多选不破坏现有单项预览、资料编辑和打开目录功能。
4. 批量资料和批量显示名称在一个事务中提交，任何错误均不产生部分修改。
5. 预览和执行使用同一个命名引擎，结果不存在漂移。
6. 编号顺序、资料连接顺序和排序具有确定性。
7. 非法名称阻止整批，重复名称只警告。
8. 命名预设持久化且只能手动执行，未知版本不能降级运行。
9. 一次性撤销按版本原子恢复，不形成持久化历史或第二套状态机。
10. 所有批量操作只修改数据库资料，不改变任何物理文件事实。
11. Desktop 不包含 SQL、资料关联查询或命名持久化规则；Infrastructure 不包含 WinUI 状态。
12. 日志不泄露用户路径、文件名、资料、规则文本、哈希或生成名称。
13. 完整自动化测试、Release 构建、离线包探针和本机人工验收通过。

## 20. 已知发布门槛

当前没有可用的干净 Windows 11 x64 虚拟机或另一台全新机器。本机受限 `PATH` 离线烟雾和人工验收不能替代“没有 SDK、开发工具和既有运行状态”的干净系统验证。该项继续作为正式发布门槛，不因 Stage 5B 本地通过而标记为完成。

## 21. 实施顺序约束

1. 先扩展正式库查询契约并用真实 SQLite 证明严格交集和稳定排序，再连接筛选 UI。
2. 先建立正式资产选择快照和多选状态，再开放批量编辑入口。
3. 先以测试驱动实现纯命名规则引擎和预设版本模型，再实现大型对话框。
4. 先让拟议资料与命名预览在应用层形成一致快照，再实现原子持久化。
5. 先证明资料和显示名称能够完整回滚，再开放应用按钮。
6. 先证明撤销的版本校验和原子性，再显示撤销入口。
7. 所有应用和集成测试通过后才扩展包探针和制作离线测试包。
8. 自动包级烟雾通过后再进入人工验收。

本规格没有遗留产品选择。实施中的类型和方法命名可以贴合现有代码，但不得削弱严格交集筛选、确定编号顺序、预览与执行同源、资料与显示名称原子提交、一次性版本化撤销以及不修改物理文件的边界。
