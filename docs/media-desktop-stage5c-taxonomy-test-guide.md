# TraceFold Media Desktop Stage 5C-A 人工验收指南

## 验收前准备

使用本次交付的 `TraceFold-MediaDesktop-Stage5C-win-x64.zip`，解压到普通本地目录。新建三个只用于验收的空目录：待入库目录、正式文件库目录和工作目录，不要复用真实资料库。准备至少 3 张图片和 2 个视频，并在软件内建立以下测试数据：

- 作者：至少 6 个，包含已引用、未使用、名称相近和准备合并的词条；
- 系列：至少 4 个，包含已引用和未使用词条；
- 内容标签：至少 6 个，包含已引用、未使用和准备合并的词条；
- 至少保留 1 个待入库项目，并正式入库至少 2 个文件；
- 让待入库项目和正式资产共同引用部分待合并词条；
- 让一项资料同时引用两个源作者或两个源标签，另一项资料预先包含目标词条。

每项检查记录“通过/失败”、操作时间、所用词条和截图。失败时先保留现场，不要立即重试覆盖证据；收集界面截图、操作步骤、包内 `logs` 对应时段日志和下方文件事实比较结果。

## 验收前文件事实

将两个路径替换为本次测试目录，运行后保留 CSV：

```powershell
$roots = @('待入库目录路径', '正式文件库路径')
$facts = foreach ($root in $roots) {
    Get-ChildItem -LiteralPath $root -File -Recurse |
        Where-Object FullName -NotMatch '[\\/]\.tracefold[\\/]' |
        ForEach-Object {
            $hash = Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256
            [pscustomobject]@{
                Root = [IO.Path]::GetFullPath($root)
                RelativePath = [IO.Path]::GetRelativePath($root, $_.FullName)
                Length = $_.Length
                LastWriteTimeUtc = $_.LastWriteTimeUtc.ToString('O')
                SHA256 = $hash.Hash
            }
        }
}
$facts | Sort-Object Root,RelativePath |
    Export-Csv .\stage5c-files-before.csv -NoTypeInformation -Encoding UTF8
```

## 19 项人工检查

### 1. 三类词表与测试数据

- 设置：打开“词表管理”，依次查看作者、系列、内容标签；核对准备好的已引用、未使用和名称相近词条。
- 操作：切换左侧三种类型并刷新。
- 预期：左栏保持紧凑；中栏只显示当前类型；右栏初始提示选择词条；类型名称为“作者 / 系列 / 内容标签”。
- 失败证据：三类列表截图、缺失或串类词条名称、对应日志。

### 2. 搜索、引用筛选与排序

- 设置：每类至少准备两个不同引用数、两个未使用和两个名称可搜索的词条。
- 操作：验证名称子串搜索、全部/已引用/未使用筛选、名称/引用数量排序及升降序。
- 预期：结果严格符合条件；引用数等于待入库与正式库引用之和；同一条件重复刷新顺序稳定。
- 失败证据：查询控件与错误结果同屏截图，注明预期和实际顺序。

### 3. Windows 式多选与三种详情状态

- 设置：当前查询至少显示 6 个词条。
- 操作：分别使用单击、`Ctrl`、`Shift`、`Ctrl+A` 和 `Esc`。
- 预期：增量选择、连续范围、全选和清空符合资源管理器习惯；右栏在 0 项、1 项和多项间正确切换并显示准确汇总。
- 失败证据：按键方式、预期范围、实际高亮和右栏摘要截图。

### 4. 单个未使用词条删除与撤销

- 设置：选择一个从未被任何资料引用的词条，记录其名称和类型。
- 操作：点击删除，核对确认列表后确认，再点击顶部撤销。
- 预期：删除后词条消失；撤销后以相同名称、类型和身份恢复；媒体文件不变。
- 失败证据：删除前、删除后、撤销后截图及错误提示。

### 5. 多个未使用词条原子删除与撤销

- 设置：在同一类型中选择至少 3 个未使用词条。
- 操作：点击删除，确认对话框列出全部词条，确认后再撤销。
- 预期：全部词条一次性删除并一次性恢复；不存在只删除或只恢复部分词条的状态。
- 失败证据：确认列表、删除结果、撤销结果和词条数量截图。

### 6. 混合选择整体阻止删除

- 设置：同时选择至少 2 个未使用词条和 2 个已引用词条。
- 操作：观察右栏阻塞清单并尝试删除。
- 预期：删除按钮禁用；阻塞清单列出每个已引用词条及引用数；未使用词条也不会被部分删除。
- 失败证据：完整选择、阻塞清单、按钮状态和操作后列表截图。

### 7. 选择内目标的多源合并

- 设置：选择同类的至少 3 个词条，其中一个作为目标，其余作为源。
- 操作：打开合并对话框，在当前选择中点选目标，核对源列表和影响预览后确认。
- 预期：目标自动从源列表移除；至少保留一个源；确认后目标保留、源删除、所有引用迁移。
- 失败证据：对话框来源/目标/预览截图及合并后词条和资料截图。

### 8. 搜索选择外部目标

- 设置：只选择一个或多个源词条，另准备一个未在当前选择中的同类目标。
- 操作：在合并对话框搜索并选择外部目标。
- 预期：全部当前选择仍是源；搜索只返回同类型现有词条；结果与选择内目标规则一致。
- 失败证据：搜索文字、结果、源列表、预览和合并后状态截图。

### 9. 作者、系列、内容标签及跨类型阻止

- 设置：三类各准备一组合并数据。
- 操作：分别完成作者、系列和内容标签预览；尝试让目标来自其他类型。
- 预期：三类均能按规则合并；目标搜索不出现其他类型；系列合并后每项资料仍最多一个系列。
- 失败证据：三类对话框和结果截图，任何跨类型候选或多系列状态。

### 10. 作者/标签去重与顺序

- 设置：资料甲依次包含“其他词条、源乙、源甲”，且不含目标；资料乙同时包含目标和多个源。
- 操作：把源甲、源乙合并到目标。
- 预期：资料甲在最早源位置放入目标，其他词条相对顺序不变；资料乙保留目标原位置并移除源；结果无重复。
- 失败证据：合并前、预览、合并后作者或标签顺序截图。

### 11. 待入库与正式库同步迁移且各增版一次

- 设置：让同一组源词条同时被一个待入库草稿和一个正式资产引用，记录两项资料当前状态。
- 操作：执行一次多源合并并分别打开两项资料。
- 预期：两处引用都迁移；预览的待入库/正式库数量准确；每个实际变化的资料所有者只产生一次版本变化，不因多个源重复增版。
- 失败证据：预览数量、两项资料合并前后详情及版本冲突表现。

### 12. 最终名称规则与第三词条冲突

- 设置：源甲名称为“名称甲”，另有不参与合并的第三词条“名称丙”。
- 操作：先把目标最终名称改为“名称甲”并预览；再改为“名称丙”。
- 预期：使用将被删除的源名称合法；使用第三词条名称时确认按钮禁用并提示应将其改选为目标。
- 失败证据：两次名称输入、按钮状态、预览或错误提示截图。

### 13. 普通重命名冲突转入预填合并

- 设置：选择词条甲，另有同类词条乙。
- 操作：把甲重命名为乙的名称，然后点击“改为合并”。
- 预期：重命名不落库、不自动合并；右栏显示冲突；合并对话框以甲为源、乙为预选目标且保留用户工作。
- 失败证据：重命名提示、右栏入口和预填对话框截图。

### 14. 陈旧预览保证零修改

- 设置：打开合并对话框并生成有效预览，不关闭；随后从另一入口修改相关资料或词条。
- 操作：返回旧对话框确认合并。
- 预期：提示预览已过期；整次操作零修改；目标、来源、最终名称和预览输入仍保留，可重新选择目标刷新。
- 失败证据：旧预览、外部修改、失败提示和操作后所有相关资料截图。

### 15. 合并撤销精确恢复

- 设置：记录目标名称、全部源词条、待入库和正式资产的原始作者/标签顺序。
- 操作：成功合并后点击撤销。
- 预期：源词条、目标原名称和所有关系顺序完整恢复；没有部分恢复；物理文件不变。
- 失败证据：合并前、合并后、撤销后三组截图与错误提示。

### 16. 相关资料漂移阻止旧撤销

- 设置：成功合并后，在相关待入库或正式资产中再做一次资料编辑。
- 操作：点击词表撤销。
- 预期：提示相关资料已变化，无法安全撤销；词条和关联均不发生部分恢复。
- 失败证据：二次编辑、撤销提示、所有相关词条和资料状态截图。

### 17. 只有最近一次维护可撤销

- 设置：连续成功完成两次不同的词表维护操作（合并或未使用删除）。
- 操作：点击一次撤销，再观察撤销入口。
- 预期：只撤销第二次操作；第一次保持；没有第二层撤销历史。普通新建或重命名后旧维护撤销也应失效。
- 失败证据：两次操作记录、一次撤销后的完整列表和撤销横幅截图。

### 18. 全程物理文件事实不变

- 设置：完成搜索、删除、合并、失败提交和撤销后，再次采集文件事实。
- 操作：运行下方命令并比较两个 CSV。
- 预期：相对路径、实际文件名、扩展名、长度、最后写入时间和 SHA-256 全部无差异；任何差异均为阻断失败。
- 失败证据：保存 `Compare-Object` 输出、资源管理器截图和涉及文件副本。

```powershell
$roots = @('待入库目录路径', '正式文件库路径')
$facts = foreach ($root in $roots) {
    Get-ChildItem -LiteralPath $root -File -Recurse |
        Where-Object FullName -NotMatch '[\\/]\.tracefold[\\/]' |
        ForEach-Object {
            [pscustomobject]@{
                Root = [IO.Path]::GetFullPath($root)
                RelativePath = [IO.Path]::GetRelativePath($root, $_.FullName)
                Length = $_.Length
                LastWriteTimeUtc = $_.LastWriteTimeUtc.ToString('O')
                SHA256 = (Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash
            }
        }
}
$facts | Sort-Object Root,RelativePath |
    Export-Csv .\stage5c-files-after.csv -NoTypeInformation -Encoding UTF8
Compare-Object `
    (Import-Csv .\stage5c-files-before.csv) `
    (Import-Csv .\stage5c-files-after.csv) `
    -Property Root,RelativePath,Length,LastWriteTimeUtc,SHA256
```

### 19. 离线 ZIP、独立窗口与进程清理

- 设置：断开网络或禁止联网；把 `PATH` 临时限制为 Windows `System32`；确认没有正在运行的本测试包进程。
- 操作：从解压目录启动 `TraceFold.Media.exe`，完成搜索、合并、删除和撤销核心路径；再次启动验证单实例；最后关闭主窗口。
- 预期：软件以独立原生窗口启动，不打开 Edge/Chrome；第二次启动回到单实例；退出后不存在来自测试包的 `TraceFold.Media.exe` 或 `tools\ffmpeg\ffmpeg.exe` 进程。
- 失败证据：任务管理器、进程可执行路径、错误窗口、是否启动浏览器、包级烟雾输出和日志。

可用以下命令检查残留进程路径：

```powershell
Get-Process TraceFold.Media,ffmpeg -ErrorAction SilentlyContinue |
    Select-Object Id,ProcessName,Path
```

## 验收结论与环境限制

只有 19 项全部通过、`Compare-Object` 无输出、Stage 5C 包级烟雾通过且退出后无残留进程，才能标记“Stage 5C-A 本机人工验收通过”。

当前没有可用的干净 Windows 11 x64 虚拟机或另一台全新机器。本机受限 `PATH`、离线烟雾和人工验收不能替代“无 SDK、无开发工具、无既有 TraceFold 状态”的干净系统发布验证。即使本指南全部通过，干净机器验证仍必须明确记录为“待验证”，不能推断为已通过。
