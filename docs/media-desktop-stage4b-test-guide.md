# TraceFold Media Desktop Stage 4B 人工验收指南

本轮验收入库中断恢复、替换备份和延迟清理。所有文件必须是复制件，所有目录必须属于本轮新建的隔离测试根；不要使用个人待入库目录或正式媒体库。

## 一、准备

1. 解压 `TraceFold-MediaDesktop-Stage4B-win-x64.zip`。
2. 新建专用目录，例如 `T:\TraceFold-Stage4B-Acceptance`，并在其中新建 `data`、`inbox`、`library`、`work`、`fixtures`。
3. 在 `fixtures` 中准备两张内容不同的图片 `image-a.jpg`、`image-b.jpg`，一个普通视频，以及同名 `paired.mp4`、`paired.m4a`。
4. 从解压目录的 PowerShell 启动：

   ```powershell
   $env:TRACEFOLD_MEDIA_DESKTOP_DATA_ROOT = 'T:\TraceFold-Stage4B-Acceptance\data'
   .\TraceFold.Media.exe
   ```

5. 在设置中选择本轮的 `inbox`、`library`、`work`，保存；自动扫描保持关闭。
6. 先按 Stage 4A 指南确认一次普通同名替换。成功时，源文件应删除，`library\.tracefold\commit` 和 `recovery` 不应保留内容。

## 二、自动故障恢复证据

发布包附带的烟雾脚本会在两个真实进程检查点强制终止软件：替换备份落盘后、正式文件提交后。随后它使用同一数据库和三个文件目录启动正常进程，验证资产 ID、目标哈希、源文件和备份清理、资产唯一性及正式库中没有未知文件。

在源码根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke-media-desktop-package.ps1 `
  -PackageDirectory 'dist\TraceFold-MediaDesktop-Stage4B-win-x64' `
  -StageCheckpoint 4B
```

预期出现：

```text
PASS: Stage 4B process-termination recovery after backup and file commit verified
```

故障种子进程的非零退出码是探针预期行为；烟雾脚本应继续启动恢复进程并最终通过。普通软件启动没有故障注入入口。

- [ ] 两个进程终止检查点均自动恢复
- [ ] 烟雾测试结束后没有 TraceFold 或 FFmpeg 残留进程

## 三、人工验收项目

### 1. 正常关闭后的状态连续性

1. 把 `image-a.jpg` 以 `photo.jpg` 入库。
2. 把 `image-b.jpg` 也命名为 `photo.jpg`，打开替换对比弹窗后直接关闭软件。
3. 重新启动，选中该项目并点击“处理冲突”。
4. 替换 `photo.jpg`。

预期：重启后仍是同一冲突；替换完成后正式库只有一个 `photo.jpg` 资产，资产实际文件名不变，源文件和内部备份被清理。

### 2. 强制终止后的自动继续或恢复

本项以第二节的自动探针作为强制终止证据，不在个人任务管理器中反复碰运气终止软件。另做一次人工观察：

1. 完成第二节烟雾测试。
2. 正常启动测试包，打开待入库和正式文件库。
3. 确认探针没有把测试资产写入人工验收目录；再执行一次普通替换。

预期：探针只使用系统临时目录；人工目录中的普通替换不受影响。自动探针证明中断发生在备份后时会继续安全替换，发生在文件提交后时会补齐数据库提交和清理；不会生成重复资产。

### 3. 外部改动导致 RecoveryBlocked

仅在本轮隔离目录操作：

1. 制造一个同名替换，并在替换过程中让目标或恢复证据发生外部变化。最稳定的方式是先复制保留测试文件，再按自动探针相同场景准备中断数据，随后在恢复进程启动前改动其目标文件内容。
2. 启动软件并选中对应待入库项。

预期：软件不猜测、不继续覆盖，项目显示“无法自动恢复，请重新检查。”；右侧出现“重新检查”和“打开文件位置”。源、目标或备份中至少保留可人工判断的副本。

操作：不改动文件时点击“重新检查”。

预期：证据仍矛盾时状态保持，不删除任何文件；修正外部改动后再次点击，只有身份重新吻合时才继续。

### 5. 锁定源文件后的有限清理重试

1. 准备一个可入库图片，在入库提交前用能够持有独占文件句柄的工具锁定对应源文件。
2. 完成正式入库。

预期：正式文件与数据库资产已完成，不回滚；项目显示“入库完成，等待再次清理。”。自动重试间隔依次为：

1. 30 秒；
2. 2 分钟；
3. 10 分钟；
4. 1 小时；
5. 此后不再本轮自动重试，等待下次启动或用户操作。

保持锁定直到第五次失败。预期状态改为“入库完成，清理需要手动重试。”，右侧显示“立即重试”。

### 6. “立即重试”清理

### 8. 两个项目互不阻塞

1. 让项目 A 因锁定源文件进入 CleanupPending。
2. 在 A 等待重试期间，把另一个图片或视频项目 B 正常入库。

预期：B 可以正常预览、标注和入库；A 的失败次数与下次重试时间独立更新。B 成功不会清除 A 的状态，A 的重试也不会改动 B。
