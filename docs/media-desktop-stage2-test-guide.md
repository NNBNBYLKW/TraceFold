# TraceFold Media Desktop Stage 2 手工验收指南

## 验收前提

- 使用测试包 `TraceFold-MediaDesktop-Stage2-win-x64.zip` 解压后的 `TraceFold.Media.exe`。
- 新建三个专用测试文件夹：“待入库”、“正式库”和“工作目录”。它们必须互不包含。
- 只使用可丢弃的文件副本。不要使用 Web 版、旧测试版或个人资料的正在使用的目录。
- 准备一张图片、一个普通 MP4 视频、一组同名 MP4/M4A，以及一个软件无法预览的文件。

## 验收步骤

1. 首次启动后进入“设置”，选择三个专用测试文件夹并保存。重启软件，确认三个路径仍然存在。
2. 将一张图片副本放入“待入库”，在软件中手动刷新。首次扫描应显示“等待文件稳定”；等待至少 2 秒后再刷新，应进入可标注/可入库状态。
3. 为该图片填写显示名称，添加多个作者、一个系列和多个内容标签。关闭后重启，确认元数据仍在。再测试不填元数据的文件，确认元数据确实可选。
4. 入库一张图片副本和一个普通视频副本。确认它们从“待入库”目录消失，出现在“正式库”目录，且实际文件名完全不变。
5. 在“正式文件库”中修改上述资料的显示名称。使用“打开所在目录”检查实际文件，确认只改变软件内显示名称，物理文件名没有改变。
6. 将同名的 `clip.mp4` 和 `clip.m4a` 副本一起放入“待入库”。刷新并等待稳定后，确认软件显示“需要前置处理”，不允许按普通文件入库，两个原文件都保留。
7. 在“正式库”预先放入一个与待入库文件同名的测试文件。尝试入库后，确认软件提示同名冲突，不覆盖正式文件，且待入库源文件保留。
8. 先成功入库一份文件，再用另一个文件名放入内容完全相同的副本。尝试入库后，确认软件提示内容冲突，且新的源文件保留。
9. 放入一个无法预览的文件和一个正常图片/视频。确认预览失败只影响对应文件，正常文件仍可标注和入库。
10. 关闭主窗口，在任务管理器中确认没有 `TraceFold.Media` 进程留存。重新启动并确认已保存的元数据和正式库记录可读取。
