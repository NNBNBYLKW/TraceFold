# TraceFold：转入 Codex 的开发教训

日期：2026-10-23（Europe/London）。依据既有项目记录及治理规范整理，未重新运行或认证历史测试。本文保存经验；旧文档中的模型分工不再作为新工作流的现行职责。

1. **先核实际外层命令，再谈整链通过。** 61正式第2轮直接调用Contract子入口，绕过Core，导致reader所需的capture文件缺失；请求Accepted和文件身份正确都没防住。以后记录真正提交的完整argv、工作目录和参数来源，核清“入口→加载依赖→消费者→结果”。同作用域单测不能替代Runner→场景→回调接缝覆盖。

2. **结果按层保存，Unknown不能补成成功。** 61目标exit1，后台shell却exit0；另一次同进程准入的LASTEXITCODE为空。目标、包装、工具退出码分别记录，未取得就写Unknown，未执行写NotRun。原生异常被脱敏投影抑制后不能猜回根因。首错与后继拒绝分别保留，报告生成成功也不代表业务成功。

3. **绑定受测源码，同时保留字节口径。** Task50曾在提交前测试而没存源码快照；另有CRLF工作树与LF Git blob不同。普通开发以准确提交、实际diff和运行记录绑定，交付时核必要文件；不能仅凭修改时间证明所跑即所交，也不能把行尾归一化等同raw逐字节相同。系统宿主补丁版本与产品固定身份分开记录。

4. **替身、原生编译、真实UI分开结论。** 61双宿主NO_PRODUCT通过，只证明限定调用链；人工重复启动回前台通过，也不能冒充完整自动合同通过。真实窗口、激活、键鼠、主题恢复各需对应观察，截图生成不等于布局正确。优先验证真正接缝，避免增加大量模型断言却遗漏生产调用。

5. **引入框架必须能退役自研代码。** ATOPT试点发现Pester只查FailedCount会漏AfterAll的FailedBlocks，NUnit全Success也可能与整轮失败并存。成熟框架和TRX用于减少执行、统计、报告代码；仍结合框架整体状态和真实退出。先用小样比较收益，再决定迁移，不给不推广候选继续堆外围工具。

6. **首次失败和旧原件不能被“收尾”覆盖。** 历史发生过同名表覆盖、失败目录删除及汇总改写。修改前保留必要基线，新运行用新输出叶；更正另写说明，不追改原失败。已经缺失的证据诚实标缺失，不重建成历史原件。清理临时文件先按用途、依赖和归属分类，不能把有用候选当缓存删除。

7. **清理只针对准确owned对象。** 使用本轮持有句柄及PID、出生时间、映像身份核归属；不按进程名结束，不接管未知残留。临时数据根与用户数据隔离，主题等环境变更保存原值并恢复。资源查询只证明当时观察范围；不能要求全机PowerShell为零，也不能拿旧查询签持续空闲。工具拒绝后停止对应动作，不换等效工具绕过。

8. **先认准工作树，再合并活动修改。** 迁移前实施仓为`T:/TraceFold5CC`；当前唯一活动工作区以CURRENT-STATE.md为准，旧检出只读，不因当前目录方便就替代。活动Runner.Tests曾缺已提交Metadata断言，Evidence.Tests也有旧版本残差；整文件暂存会撤销已接受覆盖。以新HEAD逐hunk叠加真实语义，保留未提交改动，不能默认reset或覆盖。测试数量、文件hash数量和报告数量不作进度指标。

9. **棘手问题要借助已有工具与外部思路，不能在同一路线上反复空转。** 遇到棘手问题尽早检索官方文档、维护方仓库和原始问题记录，筛选现有工具、框架或路线，并在授权范围内做最小验证。连续两轮同类修复仍无核心推进就停止重复，经协调员交reviewer定位、攻坚者处理，由助理与总负责人重新判断方案。攻坚者仍无法解决或工作流无法定位时，向总负责人报告并暂停该任务，由总负责人向用户询问下一步，等待明确答复。

新工作流按根AGENTS.md设总负责人、助理、协调员、执行者、reviewer、攻坚者六名独立成员，替换迁移初期“一个主开发对话承担实现闭包”的约定。普通实现与回归由执行者连续完成，协调员派发及跟踪，reviewer独立复核，总负责人和助理负责方案与路线判断。共享写域保持单一owner；攻坚移交先停止原写入与运行。此次只确定工作流，不恢复开发或建立成员会话。

旧多模型调度、用户逐卡转发、毫秒资源池、grant/authority及聊天通知QPC均作为历史路线退役，不复制成新Codex默认门禁；历史账、失败及未验收状态继续保留。61自动未验收和既有人工通过分列，本文不恢复旧运行许可，也不放宽数据隔离、准确归属与安全清理要求。
