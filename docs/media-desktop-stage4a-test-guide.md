# TraceFold Media Desktop Stage 4A 人工验收指南

本轮只验收“冲突识别、对比和决策”。所有操作都应使用复制件和全新的隔离目录，不要使用个人正式媒体库。

## 一、一次性准备

1. 解压 `TraceFold-MediaDesktop-Stage4A-win-x64.zip`。
2. 新建一个专用根目录，例如 `T:\TraceFold-Stage4A-Acceptance`，并在其中新建：
   - `data`：本轮独立数据库和日志；
   - `inbox`：待入库目录；
   - `library`：正式文件库；
   - `work`：工作目录；
   - `fixtures`：只保存测试原件，不在软件中配置。
3. 在 `fixtures` 中准备：
   - `image-a.jpg`：可正常预览的图片；
   - `image-b.jpg`：内容与 A 不同的图片；
   - `video-a.mp4`：普通视频；
   - `paired.mp4` 和同名 `paired.m4a`：需要合并的一对文件。
4. 在 PowerShell 中从解压目录启动，使数据完全隔离：

   ```powershell
   $env:TRACEFOLD_MEDIA_DESKTOP_DATA_ROOT = 'T:\TraceFold-Stage4A-Acceptance\data'
   .\TraceFold.Media.exe
   ```

5. 在“设置”中配置 `inbox`、`library`、`work` 三个目录，保存设置；自动扫描保持关闭。
6. 每次复制文件到 `inbox` 后，等待文件复制完成，再点击“立即刷新”。如果仍显示“等待文件稳定”，稍等片刻后再次刷新。

除非步骤明确要求，否则不要在冲突弹窗外手工移动或删除 `inbox`、`library` 中的测试文件。

## 二、验收项目

### 1. 已登记文件的同名冲突

准备：

1. 把 `image-a.jpg` 复制到 `inbox`，保持文件名为 `photo.jpg`。
2. 刷新，填写显示名称“旧图片”、作者“作者甲”、系列“系列甲”、标签“旧标签”，正式入库。
3. 把内容不同的 `image-b.jpg` 再复制到 `inbox`，同样命名为 `photo.jpg`，刷新并点击“正式入库”。

操作：只查看弹窗，不作决定。

预期 UI：

- 出现原生“发现相同或重复文件”弹窗；
- 左侧显示待入库图片，右侧列出一个 `photo.jpg`；
- 右侧匹配项显示“已登记到媒体库”和“文件同名”；
- 同名项默认选中，“替换所选文件”可用。

预期正式文件：`library\photo.jpg` 仍是 `image-a.jpg` 的内容。

预期源文件：`inbox\photo.jpg` 保留。

### 2. 仅内容相同且有多个可选目标

准备：先关闭上一步弹窗，再将该冲突选择“跳过”；随后：

1. 分别把 `image-a.jpg` 复制为 `first.jpg`、`second.jpg`，逐个完成入库；第二个文件若出现内容冲突，选择“两者都保留”。
2. 再把 `image-a.jpg` 复制为 `duplicate.jpg`，刷新并正式入库。

操作：在右侧匹配列表中切换选择 `first.jpg` 和 `second.jpg`。

预期 UI：

- 两个匹配项都显示“内容相同”，不显示“文件同名”；
- 初次打开时不自动选择任何内容目标，“替换所选文件”不可用；
- 手动选择一个目标后，替换按钮才可用；
- 左右预览、实际文件名、大小、时间和标签资料随选择正确显示。

预期正式文件：本步骤尚未决策，`first.jpg`、`second.jpg` 均不变化。

预期源文件：`duplicate.jpg` 保留。

### 4. 关闭、Esc、重启与重新打开

准备：保持第 3 项的组合冲突弹窗打开。

操作：

1. 按 `Esc` 关闭弹窗；确认没有执行跳过或替换。
2. 在右侧详情栏点击“处理冲突”，确认同一冲突重新打开。
3. 再次关闭弹窗，正常关闭软件。
4. 使用相同 PowerShell 环境变量重新启动软件，选中该待入库项，再点“处理冲突”。

预期 UI：

- `Esc` 或窗口关闭只关闭弹窗，卡片仍为“存在冲突”；
- 右侧一直提供“处理冲突”按钮；
- 重启后匹配项和默认同名选择仍然存在；
- 关闭动作不会显示“已跳过”。

预期正式文件：`library\first.jpg` 不变化。

预期源文件：`inbox\first.jpg` 在关闭和重启后都保留。

### 6. 两者都保留的后缀和显示名称

准备：

1. 清走第 5 项保留的 `inbox\first.jpg` 测试复制件。
2. 确保 `library\photo.jpg` 已登记；把任意不同文件复制为 `library\photo (2).jpg`，该占位文件无需登记。
3. 把 `image-a.jpg` 再复制为 `inbox\photo.jpg`，刷新。
4. 将显示名称改为“保留副本显示名”，正式入库。

操作：在冲突弹窗点击“两者都保留”。

预期 UI：入库完成，新资产在正式文件库列表中显示为“保留副本显示名”。

预期正式文件：

- 原 `photo.jpg` 和占位 `photo (2).jpg` 不变化；
- 新文件名为 `photo (3).jpg`；
- 物理文件名使用后缀，但显示名称仍为“保留副本显示名”。

预期源文件：`inbox\photo.jpg` 在成功后删除。

### 7. 已登记替换保留身份并更新资料

准备：

1. 记录正式文件库中已登记 `photo.jpg` 的显示名称、作者、系列和标签。
2. 把内容不同的 `image-b.jpg` 复制为 `inbox\photo.jpg`。
3. 刷新，将资料改为显示名称“替换后的图片”、两位作者“作者乙/作者丙”、系列“系列乙”、标签“新标签甲/新标签乙”。

操作：正式入库，在弹窗中确认选中已登记 `photo.jpg`，点击“替换所选文件”。

预期 UI：

- 入库完成；
- 正式文件库中仍只有原来的 `photo.jpg` 条目，没有新增同名资产；
- 显示名称及全部作者、系列、标签更新为新资料。

预期正式文件：`library\photo.jpg` 内容变为 `image-b.jpg`，实际文件名仍为 `photo.jpg`；`library\.tracefold\recovery` 与 `commit` 下没有残留文件。

预期源文件：`inbox\photo.jpg` 在全部提交成功后删除。

### 9. 源文件或目标文件变化时必须重新确认

源文件变化：

1. 制造一个同名冲突并保持弹窗打开。
2. 在资源管理器中用另一份图片覆盖对应的 `inbox` 文件。
3. 回到弹窗点击替换。

预期：软件提示冲突内容已变化或要求重新刷新；不覆盖正式文件；变化后的源文件保留。

目标文件变化：

1. 再制造一个同名冲突并保持弹窗打开。
2. 用另一份复制件覆盖右侧选中的 `library` 目标。
3. 回到弹窗点击替换。

预期：旧冲突失效并出现需要重新确认的新冲突；软件不使用旧选择覆盖变化后的目标；源文件保留。

预期正式文件：两种变化场景都不得被旧弹窗中的决定覆盖。

预期源文件：两种变化场景都保留。

### 10. 图片和处理后视频走同一冲突规则

图片路径：任选前述图片冲突，确认图片预览可显示，且关闭、保留、替换规则一致。

处理后视频路径：

1. 把 `paired.mp4`、`paired.m4a` 复制到 `inbox`，刷新并完成“开始前置处理”。
2. 在正式入库前，把另一份视频直接复制为 `library\paired.mp4`，制造未登记同名目标。
3. 点击正式入库。

操作：先关闭一次冲突弹窗，再从详情栏重新打开；随后选择未登记 `paired.mp4` 并替换。

预期 UI：

- 关闭弹窗后仍可重新处理；
- 视频冲突对比显示视频预览和媒体属性；
- 替换成功后显示入库完成。

预期正式文件：`library\paired.mp4` 是合并后的有效视频，包含视频和音频；内部提交/恢复目录无残留。

预期源文件：

- 在关闭弹窗和冲突未解决期间，原 `paired.mp4`、`paired.m4a` 都保留；
- 只有替换、数据库提交和验证全部成功后，两个原文件及处理输出才删除。
