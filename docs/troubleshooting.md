# 常见问题与排查

适用于 [v4.0.0-stage5cc 预发布版](https://github.com/NNBNBYLKW/TraceFold/releases/tag/v4.0.0-stage5cc)。第一次使用请先看[快速开始](getting-started.md)。

## 下载后找不到程序，或双击无法启动

1. 确认下载的是 `TraceFold-MediaDesktop-Stage5C-C-win-x64.zip`。带 `UiAcceptance` 的 ZIP 是开发验收工具包；GitHub 的 `Source code` 是源码。
2. 在资源管理器中右键产品 ZIP，选择“全部解压缩”，完成后进入解压目录运行 `TraceFold.Media.exe`。不要在 ZIP 预览里直接运行，也不要只把 EXE 单独拖出来。
3. 保留 EXE 同目录下的依赖文件和 `tools` 目录。如果文件缺失，重新下载并完整解压到一个新目录。
4. 按 `Win+R`，输入 `winver` 查看 Windows 版本；在 Windows“设置 → 系统 → 系统信息”查看系统类型。当前包面向 **Windows 11 24H2（build 26100）或更新的 x64 Windows**；尚未完成全部系统版本和干净虚拟机验证。
5. 包按 .NET、Windows App SDK 自包含方式构建，并随附 FFmpeg/FFprobe。通常无需另装这些组件；若仍失败，请记录完整错误文字和发生时间，按[反馈指南](../SUPPORT.md)报告。若系统显示安全提示，先核对下载来源和下方校验值。

### 可选：核对下载完整性

在 Release 下载 `SHA256SUMS.txt`。在 PowerShell 中执行下面命令，把路径换成你下载的产品 ZIP 路径，再与清单中同名文件的 SHA-256 比较：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'D:\Downloads\TraceFold-MediaDesktop-Stage5C-C-win-x64.zip'
```

校验值不一致时重新下载，不继续使用该副本。

## 设置提示三个目录有冲突

到“设置 → 文件夹与扫描”，给“待入库目录”“工作目录”“正式文件库”分别选择目录，再点“保存设置”。三个目录不能相同，也不能互相包含。可以使用同一父目录下的三个并列子目录；避免把其中一个设为另外两个的父目录。首次操作先用素材副本。

## 待入库里没有看到刚放进去的文件

- 检查“设置 → 文件夹与扫描”中的待入库路径并确认已保存，然后到“待入库”点“立即刷新”。自动扫描默认关闭，可按需在设置中打开。
- 等待文件复制完成，避免边写入边扫描。若条目有状态提示，先按提示处理。
- 同名 MP4/M4A 配对走前置处理流程，例如 `clip.mp4` 与 `clip.m4a`；选中条目后点“开始前置处理”。普通照片和普通视频可直接走预览、资料编辑和正式入库流程。

## 处理完成了，为什么正式文件库仍然没有？

前置处理只生成可供检查的结果。处理完成后，确认预览和资料，再点“正式入库”；有冲突时需要完成冲突选择。完成后到“正式文件库”查找对应条目。不要仅凭“处理完成”判断入库已成功。

## 正式入库会保留原文件吗？

**成功入库会清理对应的待入库源文件。** 配对 MP4/M4A 在处理阶段保留原文件；正式入库、冲突决策、正式文件提交和数据库提交验证成功后，会清理对应 MP4、M4A 和处理工作输出。需要独立保留原件时，请在入库前另做备份。

失败、中断、关闭冲突弹窗或发现源/目标变化时，流程不会把它当作成功并直接删除原文件。出现“重新检查”“立即重试”或清理异常时，先看当前条目提示；不要自行删除工作目录、数据库或恢复记录来消除提示。仍无法继续时保留现场并反馈错误文字。

## 资料编辑后没有保存，或改名后磁盘文件名没变

- 显示名称、作者、系列和内容标签采用自动保存；输入词条后先从候选中选中，或按 `Enter` 确认成词条，再等待保存。仅输入文本未确认，不等于已经添加。
- 切换到另一条目再回来，检查资料是否读回。若提示“资料保存失败”或“资料已在其他位置更新”，按提示重新确认，不把当前文本当作保存成功。
- 显示名称与物理文件名分离。修改显示名称不会直接重命名磁盘文件。
- “保存设置”用于文件夹设置；资料编辑不是通过这个按钮保存。

## 去哪里查看版本、诊断和日志？

打开“设置 → 系统诊断”，点“重新检查”。展开“日志与运行环境”下的诊断项，可查看产品版本、信息版本、Windows 运行环境和日志位置；可用“复制摘要”或相关条目的“复制错误代码”。“打开日志目录”可打开本次使用的数据根中的日志目录。

默认位置如下，可直接粘贴到资源管理器地址栏：

| 内容 | 默认位置 |
|---|---|
| 应用数据 | `%LOCALAPPDATA%\TraceFold\MediaDesktop` |
| 日志 | `%LOCALAPPDATA%\TraceFold\MediaDesktop\logs`（`tracefold-*.log`） |
| 本地数据库 | `%LOCALAPPDATA%\TraceFold\MediaDesktop\media-desktop.db` |

如果启动环境设置了自定义数据根，默认位置会不同，以系统诊断显示为准。应用数据目录不同于你在设置中选择的正式文件库，重装或换解压目录不会自动重置这些资料。

程序在日志初始化前就失败时，可能没有本次日志；此时提供系统错误文字、发生时间、所下载附件名和 Windows 版本即可。无需为了反馈删除或重建应用数据。
